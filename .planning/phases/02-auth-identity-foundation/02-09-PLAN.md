`## 0. `## 1. Flusso di login (BE-AUTH-01)` — sequenza numerata: (1) l'app genera `code_verifier` (43–128 char, alfabeto `[A-Za-z0-9._~-]`, regex `CODE_VERIFIER_PATTERN`) e `challenge = base64url(sha256(verifier))` (43 char, `CODE_CHALLENGE_PATTERN`); (2) apre nel browser di sistema `GET {BE}/auth/twitch/start?challenge=<challenge>`; (3) il BE fa 302 a `https://id.twitch.tv/oauth2/authorize` con `response_type=code`, `scope=` vuoto, `force_verify=true`, `state` firmato (TTL 600 s); (4) Twitch torna su `{BE}/auth/twitch/callback`; (5) il BE scambia il code, valida su `/oauth2/validate`, verifica il `client_id`, risolve/crea lo User per `twitchId` (nuovo utente: `role: adventurer`, `twitchPoints: 0`, `currentCharacter: null`), revoca il token Twitch e fa 302 a `klimmeck://auth?ticket=<ticket>` (TTL 60 s, monouso); (6) l'app chiama la mutation `exchangeLoginTicket(ticket, codeVerifier)` → `AuthSession`. Tabella degli errori del redirect `klimmeck://auth?error=<code>` con TUTTI i valori di `TwitchLoginErrorCode` e quando si verificano. Esempio GraphQL completo della mutation con selection set `{ accessToken accessTokenExpiresAt refreshToken user { id twitchId role twitchPoints } }`.

`## 2. AuthSession e sessione` — shape esatta da `src/schema.gql` (blocco SDL copiato); claims dell'access JWT `{ sub, twitchId, role, sid }`, HS256, `aud: klimmeck-api`, `iss: klimmeck-guide-be`, TTL 900 s; `accessTokenExpiresAt` è DateTime ISO; refresh token opaco, sliding 30 gg; `refreshSession(refreshToken)` pubblica → nuova coppia e il ruolo è riletto dal DB (un cambio ruolo diventa effettivo al refresh successivo, D-10); grace 30 s sul refresh token immediatamente precedente, oltre la quale il suo riuso revoca la sessione (`SESSION_REVOKED`); **single-flight del refresh lato FE obbligatorio** (solo l'ultima coppia emessa è valida); query `me: User!` per riallineare l'utente al bootstrap; mutation `logout: Boolean!` (autenticata) revoca la sessione corrente.

`## 3. HTTP e REST` — header `Authorization: Bearer <accessToken>` su `POST /api/graphql` e su tutti gli endpoint REST, Cloudinary incluso (`/cloudinary/getUrls`, `/cloudinary/getSubfoldersUrls`, `/cloudinary/uploadImage`); elenco ESATTO degli handler pubblici (i 5 asseriti in `test/app.int-spec.ts`); errori GraphQL con HTTP 200 e `errors[0].extensions.code`; REST 401 con body `{ statusCode: 401, error: 'Unauthorized', message, code }`.

`## 4. WebSocket (BE-AUTH-03 — chiude Open Question #1 FE Phase 11)` — URL `ws(s)://{host}/api/graphql`, subprotocol `graphql-transport-ws` (graphql-ws); payload `connection_init` = `{ "Authorization": "Bearer <accessToken>" }` (accettata anche la chiave `authorization`); nessun header sull'upgrade richiesto; close **4403** `Forbidden` = rifiutato al connect (token assente/invalido/scaduto); close **4401** reason `Token expired` = JWT scaduto su socket vivo; nessun canale legacy `subscriptions-transport-ws`. Requisiti FE: (a) `initialPayload` deve leggere il token CORRENTE a ogni connessione (oggi `graphql_client_provider.dart` cattura `bootstrapToken` una volta: va bene solo per il token dev statico); (b) su 4401/4403 fare refresh PRIMA di riconnettere e limitare i retry (il client Dart `graphql` 5.2.1 con `autoReconnect: true` riconnette per qualunque close code → loop con token morto); `onConnectionLost(code, reason)` è il punto d'aggancio.

`## 5. Codici d'errore` — tabella dei 4 `AuthErrorCode` (`UNAUTHENTICATED`, `SESSION_EXPIRED`, `SESSION_REVOKED`, `LOGIN_TICKET_INVALID`) con messaggio esatto da `auth.exception.ts`, quando si verifica e azione FE raccomandata (UNAUTHENTICATED → refresh e retry una volta; SESSION_EXPIRED / SESSION_REVOKED → sign-in; LOGIN_TICKET_INVALID → ricominciare il login). Nota: `extensions` degli errori auth contiene solo `code` (nessun `originalError`/`stacktrace`).

`## 6.
