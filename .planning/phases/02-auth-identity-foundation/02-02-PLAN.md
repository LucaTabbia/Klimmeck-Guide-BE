```typescript
async rotate(refreshToken: string): Promise<IssuedRefreshToken> {
    const now = this.clock.now();
    const presentedHash = sha256Hex(refreshToken);
    const nextToken = generateOpaqueToken();
    const nextHash = sha256Hex(nextToken);
    const rotated =
        (await this.rotateCurrent(presentedHash, nextHash, now)) ??
        (await this.rotateWithinGrace(presentedHash, nextHash, now));
    if (!rotated) return this.rejectRefresh(presentedHash, now);
    return { sessionId: rotated.id, userId: rotated.userId.toString(), refreshToken: nextToken };
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → refreshSession (futuro, 02-06) | Il refresh token arriva da un client non fidato e può essere rubato o riusato |
| DB sessions | Un dump del DB non deve permettere di impersonare sessioni |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-refresh-reuse | Spoofing | `SessionService.rotate` | mitigate | Rotazione a ogni uso; riuso del token precedente fuori grace 30 s → revoca sessione + SESSION_REVOKED; test dedicati |
| T-2-refresh-at-rest | Information Disclosure | collection `sessions` | mitigate | Solo `sha256Hex` del token opaco a 256 bit; test che il token in chiaro non compare nel documento |
| T-2-refresh-race | Tampering | rotate concorrenti | mitigate | `findOneAndUpdate` atomico filtrato sull'hash corrente; test Promise.all → una sola sessione, un solo token corrente |
| T-2-stale-ttl | Elevation of Privilege | TTL index | mitigate | Filtro `expiresAt > now` e `revokedAt: null` in ogni query (Pitfall 6) |
| T-2-log-leak | Information Disclosure | logger SessionService | mitigate | Log solo dell'id sessione, mai token/hash |
| T-2-dup-identity | Spoofing | indice users.twitchId su dati esistenti | mitigate | `TwitchIdIndexVerifier` logga i duplicati al boot; dedup documentato in BACKEND-NOTES |
| T-2-grace-window | Spoofing | grace 30 s (D-26) | accept | Un token rubato e usato entro 30 s dalla rotazione legittima emette una coppia nuova; finestra breve, scelta raccomandata (A3) da confermare con l'utente |
