# Phase 03.1 Plan 05: deleteCharacter mutation Summary

**`deleteCharacter: User!` archives the caller's current character in a single Mongo transaction. The user is unlinked first with an inverse conditional claim (`currentCharacter: { $ne: null }`, `returnDocument: 'before'`), then the character is archived with `updateOne(activeCharacterById(prev), { deletedAt, deletionReason })`. Concurrent losers, second calls and users without a character get `CHARACTER_NOT_FOUND`. A valid bearer for a deleted user gets `UNAUTHENTICATED`.**
