# Phase 03.1 - Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| client GraphQL -> `Character` / `CharacterInput` | nessun campo di archivio attraversa il confine | `deletedAt`, `deletionReason` (mai esposti) |
| client -> `deleteCharacter` | mutation distruttiva senza input; identita solo dal JWT | bearer token |
| client -> `id` / `request.id` / `request.characterId` | id non fidato, puo puntare a un archiviato | ObjectId |
| guard ownership -> service | il guard decide, il service rilegge filtrando gli attivi | ownership decision |
| resolver -> transazione Mongo | `users` + `characters` scritte atomicamente | stato di gioco |
| MongoDB change stream -> PubSub -> client WS | eventi `characterUpdated` / `userUpdated` | stato personaggio |
| coda Bull -> processor | job accodati prima dell'archivio scattano dopo | characterId, spellId |
| boot app -> MongoDB (DDL) | `createIndexes` / `dropIndex` su `characters` | nomi indice |
| documentazione BE -> team FE / fasi future | regole del filtro attivo | BACKEND-NOTES |
