## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Contract
- **D-01:** Mutation **`deleteCharacter: User!`** with **no arguments**. Identity only from `@CurrentUser()` (BE-AUTH-06): it acts on the caller's `currentCharacter`. No `id` argument — it would be redundant and would open an ownership path to protect. Returns the updated `User` with `currentCharacter: null` (same shape as `me` / `createCharacter`), so the app swaps its session user without a second round trip (FE D-17).
- **D-02:** Lives next to the creation code (`src/characters/creation/` → consider renaming the module to a lifecycle module, or a sibling `src/characters/deletion/`; planner's choice, Boy Scout on naming). Mounted in `AppModule`, covered by the real-boot schema test.
- **D-03:** Stable codes in `errors[0].extensions.code`, Phase 2/02.1 pattern (typed exception with `extensions.code`): **`CHARACTER_NOT_FOUND`** when the caller has no current character (second call, loser of two concurrent calls, stale client); `UNAUTHENTICATED` from the auth pipeline. Messages are Italian and user-facing; codes never change.

#### Soft delete semantics (user decision 2026-10-15: archive, never purge)
- **D-04:** The `Character` document **stays in the collection**, marked with **`deletedAt: Date`** (default `null` on every existing/new document) and **`deletionReason`** (`user_request` now; `death` reserved for Phase 9). No other field is altered: name, status, quests and assets remain readable for audit and future mechanics.
- **D-05:** **Atomic unlink, same pattern as creation (02.1 D-03/D-17):** inside a replica-set transaction, (1) claim the user with `findOneAndUpdate({ _id: userId, currentCharacter: { $ne: null } }, { $set: { currentCharacter: null } })` capturing the previous id, (2) `updateOne({ _id: characterId, deletedAt: null }, { $set: { deletedAt, deletionReason } })`. If the claim finds no character → `CHARACTER_NOT_FOUND`, nothing written. Two concurrent calls → exactly one archive, the loser gets `CHARACTER_NOT_FOUND` (driver retries `WriteConflict`, as in 02.1). The response `User` is re-read after the commit (populated `currentCharacter` = `null`).
- **D-06:** **Archived characters are invisible on player paths** — fail-closed, the same way as a non-existent id: `character(id)` → `NOT_FOUND`; `characterUpdated(id)` → rejected at subscribe like a foreign id (`FORBIDDEN`/`NOT_FOUND`, planner picks the code already used by Phase 3 for "not yours"); every ownership-guarded mutation on an archived id is refused; the Bull spell-recovery processor and every future job (travel, Phase 8) must filter `deletedAt: null`. A single shared query helper/filter (e.g. `activeCharacterFilter`) is preferred over scattered conditions. The innkeeper-only `characters` list may include archived documents **only** behind an explicit argument (default: exclude) — planner's choice, additive.
- **D-07:** **No `characterUpdated` for archived documents:** the characters change-stream publisher skips `fullDocument.deletedAt != null` (the archiving update itself would otherwise emit one last event). Belt and braces with the Phase 3 ownership re-filter (the owner no longer owns it).
- **D-08:** **`userUpdated` needs no code:** the `users` change stream (Phase 3 D-02) already emits the full `User` on the `currentCharacter: null` update. Covered by an integration test on the wire.

#### Name release
- **D-09:** The archived character's **name becomes available again** for `createCharacter` (FE E2E: delete → recreate with the same name). The case-insensitive unique index `character_name_ci_unique` (02.1 D-05, `CharacterNameIndexVerifier`) must stop covering archived documents. Options for the planner (research flag — verify what MongoDB 8 accepts in `partialFilterExpression`, e.g. `{ deletedAt: { $type: 'null' } }` vs a boolean `archived: false` flag; `$exists: false` is **not** allowed): **(a)** partial unique index on active documents; **(b)** a dedicated indexed key (e.g. `infos.nameKey`) `$unset` on archive, sparse unique index. Either way the boot verifier is updated to build the new index (and drop the old definition once), logging without blocking boot as in 02.1 D-32-style verifiers. `infos.name` stays readable on the archived document.

#### Pending state and cross references

Phase 7 (quest lanes) and Phase 8 (travel lifecycle) must treat archived characters as absent (D-06 filter) — recorded as a note for those phases in `BACKEND-NOTES.md`.
- **D-11:** `twitchPoints` live on the `User` and are **untouched** by deletion (FE open question 4). No cooldown or limit on re-creation (open question 3).
- **D-12:** **Audit:** `deletedAt` + `deletionReason` on the document are the trace; **no** `admin_audit_logs` record (not an admin action). Phase 9 will reuse the same archive routine with `deletionReason: death`.

## Summary

The deletion is the exact inverse of the 02.1 claim: one `connection.transaction()` that unlinks the user with `findOneAndUpdate({ _id, currentCharacter: { $ne: null } }, { $set: { currentCharacter: null } }, { returnDocument: 'before' })` and then archives the character with `updateOne({ _id: prev, deletedAt: null }, { $set: { deletedAt, deletionReason } })`. I ran this pattern on Mongoose 8.18.1 against a MongoMemoryReplSet: three concurrent calls → `['err CHARACTER_NOT_FOUND attempts=2', 'ok attempts=1', 'err CHARACTER_NOT_FOUND attempts=2']`. The driver retries the WriteConflict on its own, and the retry finds `currentCharacter: null`.

**The research flag in D-09 rests on a false premise.** `partialFilterExpression: { deletedAt: null }` (and `{ deletedAt: { $eq: null } }`) **is accepted** on MongoDB 6.0.19, 7.0.14, 8.0.4 (the CI pin) and 8.2.6 (the local binary), and the index **covers documents where `deletedAt` is missing**. So the existing production characters, which have no `deletedAt` field, stay protected with no backfill. `{ $type: 'null' }` and `{ archived: false }` are both accepted too, but they do **not** cover missing fields. They would silently drop uniqueness for every legacy character unless a backfill ran first. `$exists: false` and `$ne` are rejected with `CannotCreateIndex` (code 67, "Expression not supported in partial index: $not"). The recommendation is a partial unique index with `{ deletedAt: null }` under a **new name**. Reusing the old name fails with `IndexKeySpecsConflict` (code **86**, not 85). The verifier then drops `character_name_ci_unique` once, tolerating `IndexNotFound` (code 27). Until that legacy index is dropped, an archived name stays reserved (verified).

Invisibility is a short list of explicit filters (11 read paths, table in Q2), with no global Mongoose middleware. The key one is `CharacterAccessPolicy.assertCharacterExists`. Once it filters active documents, an archived id answers `NOT_FOUND` on every path, for the ex-owner, for other players and for the innkeeper alike, exactly like a non-existent id. The characters change stream gets `'fullDocument.deletedAt': null` in its `$match` stage, verified to suppress both the archiving update and any later write to an archived doc.

**Primary recommendation:** sibling module `src/characters/deletion/` with `CharacterDeletionService.archiveCurrentCharacter(userId, reason)` (reusable by Phase 9). Shared filter `src/models/character/active-character.filter.ts` (`ACTIVE_CHARACTER_FILTER = { deletedAt: null }`). Partial unique index `character_name_active_ci_unique` with `partialFilterExpression: ACTIVE_CHARACTER_FILTER`, plus a verifier that builds it and then drops the legacy `character_name_ci_unique`. `NOT_FOUND` for archived ids on every path.

## Answers to the research questions

### Q1 — Partial unique index for name release (D-09) — HIGH

**Empirical matrix** (script at `/private/tmp/claude-501/-Users-lucatabbia-Personale-Code-Klimmeck-Guide-BE-Klimmeck-Guide-BE/55a1144a-ea2e-4578-b117-e48f55e2315a/scratchpad/pfe.js`, run on 6.0.19, 7.0.14, 8.0.4 and 8.2.6 with identical results) [VERIFIED: mongod via mongodb-memory-server 11.2.0]:

| `partialFilterExpression` | Created? | Dup between two docs **missing** the field | Dup between two `null` docs | Archived vs active same name |
|---|---|---|---|---|
| `{ deletedAt: null }` | yes | **rejected (11000)**, so missing is covered | rejected | allowed |
| `{ deletedAt: { $eq: null } }` | yes | **rejected**, missing covered | rejected | allowed |
| `{ deletedAt: { $in: [null] } }` | yes | rejected, missing covered | rejected | allowed |
| `{ deletedAt: { $type: 'null' } }` | yes | **ALLOWED**, missing NOT covered | rejected | allowed |
| `{ archived: false }` | yes | **ALLOWED**, missing NOT covered | rejected | allowed |
| `{ deletedAt: { $exists: false } }` | **no**, code 67 `CannotCreateIndex`: "Expression not supported in partial index: $not" | — | — | — |
| `{ archived: { $ne: true } }` | **no**, code 67, same message | — | — | — |

Official docs list the allowed operators as: equality (`field: value` or `$eq`), `$exists: true`, `$gt/$gte/$lt/$lte`, `$type`, `$and`, `$or`, `$in`, `$geoWithin`, `$geoIntersects`. With a unique constraint, uniqueness "only applies to the documents that meet the filter expression" [CITED: mongodb.com/docs/manual/core/index-partial/]. The docs do not mention null equality explicitly. The matrix above is the evidence.

**Decision: option (a), partial unique index with `{ deletedAt: null }`.**
- It covers legacy documents without the field, so **no backfill or data migration** is needed (D-04's "default null on existing documents" is satisfied semantically: in a query, `{ deletedAt: null }` matches both missing and null, verified `find {deletedAt:null} → [missing, null]`).
- It uses the **same constant** as the read filter (`ACTIVE_CHARACTER_FILTER`), so "active" has one definition everywhere.
- Option (b) (`nameKey` + `$unset`) would need a backfill of every existing doc, a double write on create, and a second source of truth for the name. Rejected.
- `$type: 'null'` / boolean flag: rejected because they need a backfill to be correct, and if the backfill is missed they fail silently.

**Exact spec** (in `src/models/character/character.model.ts`):
```ts
export const CHARACTER_NAME_INDEX = 'character_name_active_ci_unique';
export const LEGACY_CHARACTER_NAME_INDEX = 'character_name_ci_unique';
CharacterSchema.index(
    { 'infos.name': 1 },
    {
        unique: true,
        collation: CHARACTER_NAME_COLLATION, // { locale: 'en', strength: 2 }
        name: CHARACTER_NAME_INDEX,
        partialFilterExpression: ACTIVE_CHARACTER_FILTER, // { deletedAt: null }
    },
);
```

**Index migration semantics** [VERIFIED: same scripts]:
- Same name `character_name_ci_unique` with an added `partialFilterExpression` → **code 86 `IndexKeySpecsConflict`** ("An existing index has the same name as the requested index"). It is not 85. The current verifier would log it as "Indexes on characters could not be built (MongoServerError, code 86)" and the old global index would stay in place, so names would never be released. **A new name is therefore required.**
- New name, same keys and same collation, partial filter added → **coexists** with the old index ("newName coexist OK"). Mongoose `autoIndex` / `createIndexes()` builds the new index without error on a DB that still has the legacy one.
- While the legacy index exists, reusing an archived name is **still rejected** with E11000 on `character_name_ci_unique` (keyPattern `{ 'infos.name': 1 }`, so it would surface as `CHARACTER_NAME_TAKEN`). The legacy drop is mandatory.
- `dropIndex('nope')` → **code 27 `IndexNotFound`**, which is the idempotent case the verifier must tolerate.
- After the drop, `Model.diffIndexes()` → `{ toDrop: [], toCreate: [] }`.
- The E11000 raised by the new index still has `keyPattern: { 'infos.name': 1 }`, so `isDuplicateKeyOn(error, 'infos.name')` and `CHARACTER_NAME_TAKEN` keep working unchanged.

**Verifier sequence** (`CharacterNameIndexVerifier.onApplicationBootstrap`):
1. `await characterModel.createIndexes()`. On failure, keep the current logging (E11000 → collision message using `CHARACTER_NAME_INDEX`; other → `describeMongoError`) and **return without dropping the legacy index**: a failed partial build must never leave the collection with no uniqueness at all.
2. `await characterModel.collection.dropIndex(LEGACY_CHARACTER_NAME_INDEX)`. Success → `logger.log` once. Code 27 → silent (already migrated / fresh DB). Any other error → `logger.error` explaining that archived names stay reserved until the legacy index is dropped by hand. Never throw.
3. Add `INDEX_NOT_FOUND_ERROR_CODE = 27` + `isIndexNotFoundError()` to `src/mongo/mongo-errors.ts` (unit-test it like `isDuplicateKeyError`).

Do **not** use `Model.syncIndexes()`. It would also drop any index created outside the schema (wider blast radius than needed) [ASSUMED: no hand-made indexes exist on prod `characters`, which is unverifiable from here, hence the explicit by-name drop].

**Harness binaries:** mongodb-memory-server **11.2.0**, local cached binary **mongod 8.2.6 arm64-darwin** (`node_modules/.cache/mongodb-memory-server/mongod-arm64-darwin-8.2.6`), CI pins **`MONGOMS_VERSION: '8.0.4'`** (`.github/workflows/ci.yml`). Both were verified [VERIFIED].

**Helper shape.** It goes under `src/models/character/` because the model file (index) imports it, and models must not import from `src/characters/`:
```ts
// src/models/character/active-character.filter.ts
import type { Types } from 'mongoose';

// un personaggio archiviato non esiste per i percorsi di gioco: missing e null valgono entrambi "attivo"
export const ACTIVE_CHARACTER_FILTER = { deletedAt: null } as const;

export function activeCharacterById(id: string | Types.ObjectId) {
    return { _id: id, ...ACTIVE_CHARACTER_FILTER };
}
```
Usage: `this.characterModel.findById(id)` → `this.characterModel.findOne(activeCharacterById(id))`, `exists({ _id })` → `exists(activeCharacterById(id))`, `find()` → `find(ACTIVE_CHARACTER_FILTER)`. `findById(id)` is sugar for `findOne({ _id: id })` [CITED: mongoosejs.com/docs/api/model.html#Model.findById()], so the behavior is identical, including the CastError on malformed ids. That case cannot happen in practice because the policy checks `isObjectIdHex` first.

**Global `pre('find')` middleware: recommend against.**
1. It would hide archived docs from the code that legitimately needs them: the innkeeper list with a future flag, Phase 9 death archiving, the audit, and the verifier's collision checks.
2. Mongoose query middleware is per-operation (`find`, `findOne`, `countDocuments`, `exists`, `updateOne`...) and **does not apply to `aggregate()` or change streams**, so the coverage would look complete without being complete [CITED: mongoosejs.com/docs/middleware.html].
3. It is invisible at the call site, which goes against this repo's explicit-and-tested style (Phase 3 policy).

An explicit helper plus one unit test per call site is reviewable.

### Q3 — Change-stream suppression (D-07) — HIGH

Today, `src/characters/characters.service.ts:37-60` uses `pipeline = [{ $match: { operationType: { $in: ['update', 'replace'] } } }]`, `fullDocument: 'updateLookup'`, and on `change` calls `this.findOne(id)` then `this.pubSub.publish('characterUpdated', ...)` (no await, correct: yoga `publish` returns `void`).

**Recommended form: suppress in the pipeline.** Pull the pipeline out as a named constant (like `USER_CHANGES_PIPELINE` in `src/users/user-updates.publisher.ts:16`):
```ts
const CHARACTER_CHANGES_PIPELINE = [
    {
        $match: {
            operationType: { $in: ['update', 'replace'] },
            'fullDocument.deletedAt': null,
        },
    },
];
```
Verified on 8.2.6 with `fullDocument: 'updateLookup'`: active-doc update → delivered; archiving update → **not delivered**; a later update to an already archived doc → **not delivered** (`pipeline-filtered events ["Ann2"]`) [VERIFIED: mg.js]. With `updateLookup`, the fullDocument is the current majority-committed document at lookup time, so the archiving update itself has `deletedAt` set (verified `change events [{"op":"update","deletedAt":"…"}]`). A possible race (an update on an active doc whose lookup runs after the archive) also gets suppressed, which is fail-closed and fine.

**Why the pipeline and not only the handler:** once `findOne` gets the active filter, the handler's re-read would throw `NOT_FOUND` for archived docs. Suppression would then happen by accident, through an exception logged as `Errore nel change stream` on every archive. The `$match` keeps the log clean and makes the behavior testable. Also, in the handler, treat a `ResourceNotFoundException` from the re-read as a silent skip (race: archived between event and re-read), not an `error` log. The test must assert that no `Logger.error` fired (see Validation).

Belt and braces remains: the resolver's `mayDeliver` (`src/characters/characters.resolver.ts:122-129`) rechecks ownership per event, and after the unlink the ex-owner's `currentCharacter` is `null`.

### Q4 — Codes for archived ids (D-06) — HIGH

Phase 3 behavior today (`src/authz/ownership/character-access.policy.ts:64-79`): owner → pass. Innkeeper → `onBehalf` (no existence check). Anyone else → `assertCharacterExists` → **`NOT_FOUND`** if missing, else **`FORBIDDEN`** (`AuthorizationException.notOwner()`, "Questo personaggio non ti appartiene"). Malformed id → `NOT_FOUND`. Tests: `src/characters/characters-ownership.int-spec.ts` (`it.each(OPERATIONS)` lines ~196-270: FORBIDDEN for others, NOT_FOUND for unknown/malformed for both adventurer and innkeeper), `src/characters/character-updated.subscription.int-spec.ts:184-215`.

**Recommendation: `NOT_FOUND` everywhere = "same as a non-existent id"**. This is what D-06 says first ("fail-closed, the same way as a non-existent id"), and it avoids an existence oracle on archived ids. The ex-owner of an archived id would otherwise get `FORBIDDEN` today, because it is no longer theirs but still exists:

| Path | Adventurer (ex-owner or other) | Innkeeper | Mechanism |
|---|---|---|---|
| `character(id)`, `equipment(id)` | `NOT_FOUND` | `NOT_FOUND` | policy `assertCharacterExists(active)` / service `findOne`/`getEquipment(active)` |
| `doTransaction`, `equipItem`, `equipSpell`, `unequipSpell`, `useSpell` | `NOT_FOUND` | `NOT_FOUND` (audited as on-behalf with outcome `NOT_FOUND`, like any unknown id today) | policy / service active filter |
| `characterUpdated(id)` subscribe | `NOT_FOUND` + `complete`, no snapshot | `NOT_FOUND` + `complete` (thrown by `subscribeWithSnapshot` snapshot `findOne`) | same; `ResourceNotFoundException` carries `this.extensions`, so the code survives on WS where `formatDomainError` does not run |
| `pendingQuest(id)` of an archived character | `NOT_FOUND`/`FORBIDDEN` unchanged (pending quests are not archived) | — | out of scope |

Already-open subscriptions at deletion time stay **open but silent** (no `complete`): the pipeline drops archived events and `mayDeliver` drops by ownership. The FE closes them when it unmounts the shell (FE D-08). Document this in BACKEND-NOTES.

### Q5 — Transaction for the inverse claim (D-05) — HIGH

Pattern to mirror (`src/characters/creation/character-creation.service.ts:49-74`): `this.connection.transaction(async (session) => { ... })` (Mongoose wrapper around `session.withTransaction`, which retries `TransientTransactionError`/WriteConflict and `UnknownTransactionCommitResult` automatically. No manual loop, no explicit readConcern/writeConcern). It uses `findOneAndUpdate(filter, update, { session, new: true }).exec()`, and on a null claim calls `rejectUnclaimed(userId, session)`, which distinguishes "user deleted → `AuthException.unauthenticated()`" from the domain error. The response comes from `usersService.findOne(userId)` (populates `currentCharacter`).

**Deletion routine, step by step** (verified shape, `mg.js`):
1. `deleteCharacter(userId: string): Promise<User>` → `await this.archiveCurrentCharacter(new Types.ObjectId(userId), DeletionReason.user_request); return this.usersService.findOne(userId);`
2. `archiveCurrentCharacter(userId, reason)` (public, reusable by Phase 9 with `DeletionReason.death`):
   - `const unlinked = await this.userModel.findOneAndUpdate({ _id: userId, currentCharacter: { $ne: null } }, { $set: { currentCharacter: null } }, { session, returnDocument: 'before', projection: { currentCharacter: 1 } }).lean<{ currentCharacter: Types.ObjectId | null } | null>().exec();` With `returnDocument: 'before'` it **returns the previous id** [VERIFIED]. Mongoose's default `new: false` gives the same result, but `returnDocument: 'before'` states the intent.
   - `if (!unlinked?.currentCharacter) throw await this.rejectUnlinked(userId, session);` where `rejectUnlinked` = `userModel.exists({ _id: userId }).session(session)` → `CharacterDeletionException.notFound()` if the user exists, else `AuthException.unauthenticated()` (mirror of `rejectUnclaimed`, which covers the "valid bearer, user deleted" case tested in 02.1).
   - `const archived = await this.characterModel.updateOne(activeCharacterById(unlinked.currentCharacter), { $set: { deletedAt: new Date(), deletionReason: reason } }, { session }).exec();`
   - `if (archived.matchedCount === 0) this.logger.warn(...)`. This is the dangling/already-archived reference case. **Recommendation: commit the unlink anyway** (self-healing: otherwise the user can neither create, because of `ALREADY_EXISTS`, nor delete). Planner's call; see Open Questions.
3. Concurrency [VERIFIED]: 3 parallel archives → 1 `ok attempts=1`, 2 `CHARACTER_NOT_FOUND attempts=2`; user `currentCharacter: null`; exactly one character archived.
4. `Clock` is not exported by `AuthModule` (`src/auth/auth.module.ts:57-62`), so use `new Date()`. Tests assert that `deletedAt` is a `Date` between before/after timestamps.

### Pattern 1: typed domain exception (clone of `CharacterCreationException`)
`extends NotFoundException` (404 semantics; `formatDomainError` only needs an `HttpException` with a string `extensions.code`), private constructor, `this.extensions = { code }` (needed on WS and by `formatDomainError`), static factory `notFound()` with an Italian message such as `'Non hai un personaggio da eliminare'`. Enum `CharacterDeletionErrorCode { CHARACTER_NOT_FOUND = 'CHARACTER_NOT_FOUND' }`.

### Pattern 2: identity-bound mutation returning the re-read `User`
Same as `CharacterCreationResolver.createCharacter` (`src/characters/creation/character-creation.resolver.ts:17-26`), with no `@Args`.

### Pattern 3: change-stream pipeline as a named constant (`USER_CHANGES_PIPELINE` style)
It makes the D-07 filter grep-able and unit-assertable.

### Anti-Patterns to Avoid
- **Reusing the index name `character_name_ci_unique` with new options:** code 86 at every boot, the name is never released.
- **Dropping the legacy index before the partial one is built:** a window with no uniqueness.
- **Relying on `findOne` throwing to suppress archived events:** noisy `error` logs, and the test would pass for the wrong reason.
- **Adding an `id` arg to `deleteCharacter`:** forbidden by D-01.
- **Writing an `admin_audit_logs` record:** forbidden by D-12.
- **`await this.pubSub.publish(...)`:** `publish` returns `void` (commit `76c9a3d` fixed exactly this).

## Common Pitfalls

### Pitfall 1: index name reuse → code 86, silent at boot
**What goes wrong:** names are never released in prod while the tests (fresh DB) pass.
**How to avoid:** new name + explicit legacy drop. Add an int-spec that **pre-creates the legacy index by hand** and asserts it is gone after `onApplicationBootstrap()`, and that an archived name becomes reusable.
**Warning signs:** `Indexes on characters could not be built (MongoServerError, code 86)` in the logs.

### Pitfall 2: `$type: 'null'` / boolean flag partial filters miss legacy docs
**What goes wrong:** two legacy characters can end up with case-colliding names, with no error.
**How to avoid:** use `{ deletedAt: null }` (covers missing). Unit-assert the index options from `CharacterSchema.indexes()`.

### Pitfall 3: `Date | null` without an explicit `type` → `Mixed`
**How to avoid:** `@Prop({ type: Date, default: null })`, `@Prop({ type: String, enum: Object.values(DeletionReason), default: null })`.

### Pitfall 4: unit mocks expect `findById`
`src/characters/characters.service.spec.ts:20` mocks `{ findById: jest.fn() }`. Switching the service to `findOne(activeCharacterById(id))` breaks those tests. Update the mock to `findOne` and **assert the filter** (`toHaveBeenCalledWith({ _id: id, deletedAt: null })`). That assertion is the per-path unit RED/GREEN.

### Pitfall 5: suppression by exception instead of by filter
Covered in Q3: spy on `Logger.prototype.error` in the realtime int-spec and assert it was not called with `'Errore nel change stream'`.

### Pitfall 6: `expectSilence` without a sentinel
The negative assertion is only meaningful after another subscription on the same stream received an event written **after** the archive (e.g. the innkeeper subscribed to bruno's character).

### Pitfall 7: tooling
Jest paths before `--selectProjects`; `--runInBand` for integration; `npx prettier --write <file>` + `npx eslint <file>` on touched files only (`npm run lint` runs `--fix` repo-wide). Older files such as `characters.service.ts` are not prettier-clean (4-space plus mixed style): formatting the whole file when touching it is Boy Scout, but it bloats the diff. Planner: allow it in a separate `style:` commit or format only touched regions.

### Pitfall 8: verifier int-spec asserts the old name
`character-name-index.verifier.int-spec.ts:84-97` looks up `'character_name_ci_unique'`, and `test/authz/player-fixture.ts:59` has a comment about it. Update both (the test change is the RED).

### Pitfall 9: transaction collections must exist
Call `model(name).init()` for User and Character in `beforeAll` (harness drops the DB on `close()`). Without it, the first transaction can fail creating a collection.

### Pitfall 10: the deleted-user bearer
A valid JWT for a deleted `User` must answer `UNAUTHENTICATED`, not `CHARACTER_NOT_FOUND` (mirror of the 02.1 test "rejects a valid bearer whose user no longer exists").

## Code Examples

### §1 Service core (verified shape on Mongoose 8.18.1)
```ts
// src/characters/deletion/character-deletion.service.ts (sketch)
async archiveCurrentCharacter(userId: Types.ObjectId, reason: DeletionReason): Promise<void> {
    await this.connection.transaction(async (session) => {
        // il claim inverso: solo chi ha ancora un personaggio lo scollega, il perdente concorrente trova null
        const unlinked = await this.userModel
            .findOneAndUpdate(
                { _id: userId, currentCharacter: { $ne: null } },
                { $set: { currentCharacter: null } },
                { session, returnDocument: 'before', projection: { currentCharacter: 1 } },
            )
            .lean<{ currentCharacter: Types.ObjectId | null } | null>()
            .exec();
        if (!unlinked?.currentCharacter) throw await this.rejectUnlinked(userId, session);
        const archived = await this.characterModel
            .updateOne(
                activeCharacterById(unlinked.currentCharacter),
                { $set: { deletedAt: new Date(), deletionReason: reason } },
                { session },
            )
            .exec();
        if (archived.matchedCount === 0) {
            this.logger.warn(`User ${String(userId)} pointed to a missing or archived character: unlinked anyway`);
        }
    });
}
```

### §2 Verifier
```ts
async onApplicationBootstrap(): Promise<void> {
    try {
        await this.characterModel.createIndexes();
    } catch (error) {
        this.logger.error(isDuplicateKeyError(error) ? DUPLICATED_NAMES_MESSAGE : `...${describeMongoError(error)}...`);
        return; // il vecchio indice resta: meglio nomi archiviati riservati che nessuna unicità
    }
    await this.dropLegacyNameIndex();
}

private async dropLegacyNameIndex(): Promise<void> {
    try {
        await this.characterModel.collection.dropIndex(LEGACY_CHARACTER_NAME_INDEX);
        this.logger.log(`Dropped legacy index ${LEGACY_CHARACTER_NAME_INDEX}: archived character names are reusable`);
    } catch (error) {
        if (isIndexNotFoundError(error)) return;
        this.logger.error(`Legacy index ${LEGACY_CHARACTER_NAME_INDEX} could not be dropped (${describeMongoError(error)}). Names of archived characters stay reserved until it is dropped.`);
    }
}
```

### Threat surface (for the planner's `<threat_model>`)
| Pattern | STRIDE | Mitigation |
|---|---|---|
| Deleting someone else's character | Elevation / Tampering | no args; filter `_id: identity.userId` only; JWT is the only identity source |
| Replay / double-tap / concurrent deletes | Tampering | transaction + conditional claim; loser gets `CHARACTER_NOT_FOUND`; idempotent end state |
| Probing archived ids (existence oracle: FORBIDDEN vs NOT_FOUND) | Information disclosure | archived = non-existent: `NOT_FOUND` on every path, for every role |
| Leaking archived state via the change stream | Information disclosure | pipeline `$match 'fullDocument.deletedAt': null` + ownership re-filter |
| Name squatting after release (someone grabs a just-freed name) | Spoofing (low) | accepted by design (D-11: no cooldown); the race is resolved by the unique index; document it |
| Resurrection by background jobs (spell recovery, future travel) | Tampering | active filter in the processor; BACKEND-NOTES rule for Phases 7/8/9 |
| Client writing `deletedAt` | Tampering | no `@Field`, not in `CharacterInput`; only the service sets it |
| Deleted-user bearer | Spoofing | `rejectUnlinked` → `UNAUTHENTICATED` |
| Boot DoS via index migration | Availability | verifier never throws; logs only |
