# Phase 03.1 Plan 01: Character archive foundations Summary

**Soft-delete contracts for Character: `deletedAt`/`deletionReason` as typed `@Prop` (Date / String enum, default null, not in GraphQL), the shared `ACTIVE_CHARACTER_FILTER` / `activeCharacterById` helper, and the 404 `CharacterDeletionException.notFound()` with code `CHARACTER_NOT_FOUND`.**

## Performance

- **Duration:** ~2 min (wall clock)
- **Completed:** 2026-10-16
- **Tasks:** 2/2
- **Files:** 7 created, 1 modified

## Accomplishments

- `DeletionReason` enum (`user_request`, `death` reserved for Phase 9), no `registerEnumType`.
- `Character.deletedAt` (`@Prop({ type: Date, default: null })`) and `Character.deletionReason` (`@Prop({ type: String, enum: Object.values(DeletionReason), default: null })`), no `@Field`; new documents start with both `null`, invalid reasons fail validation, `deletedAt` is `Date` and not `Mixed` (Pitfall 3).
- `ACTIVE_CHARACTER_FILTER = { deletedAt: null } as const` and `activeCharacterById(id)` returning a new `{ _id, deletedAt: null }` on each call. Plans 02 to 05 use this as the single definition.
- `CharacterDeletionException extends NotFoundException`: `notFound()` gives 404, `extensions.code` `CHARACTER_NOT_FOUND`, message `Non hai un personaggio da eliminare`.
