# Phase 03.1: Character Deletion Contract - Context

**Gathered:** 2026-10-15
**Status:** Ready for planning
**Inserted:** after Phase 3, on user directive from the FE Phase 4 discuss (2026-10-15): character deletion from Settings is *in scope now, with backend work*; *"crea direttamente il necessario anche sul repo BE."*

<domain>
## Phase Boundary

Give the frontend one authenticated mutation that **archives the caller's current character** and unlinks it from the `User`, atomically, returning the updated `User` — the mirror of `createCharacter` (Phase 02.1). The backend owns every rule: soft-delete semantics, invisibility of archived characters on player paths, release of the character name, stable error codes, the real-time side effects (`userUpdated` emits, `characterUpdated` stays silent for archived documents), and the handoff (`BACKEND-NOTES.md`) consumed by FE Phase 4 (SET-05).

Out of scope: admin deletion of other users' characters (Phase 9/10 with `@Roles(innkeeper)` + audit), death-in-combat archiving (Phase 9 reuses this path with `deletionReason: death`), physical purge of archived documents, cooldowns or limits on re-creation, any GraphQL read of archived characters, server-side notification preferences (FE keeps them on the device — see the FE notes §4).

</domain>

<decisions>
## Implementation Decisions

### Contract
- **D-01:** Mutation **`deleteCharacter: User!`** with **no arguments**. Identity only from `@CurrentUser()` (BE-AUTH-06): it acts on the caller's `currentCharacter`. No `id` argument — it would be redundant and would open an ownership path to protect. Returns the updated `User` with `currentCharacter: null` (same shape as `me` / `createCharacter`), so the app swaps its session user without a second round trip (FE D-17).
- **D-02:** Lives next to the creation code (`src/characters/creation/` → consider renaming the module to a lifecycle module, or a sibling `src/characters/deletion/`; planner's choice, Boy Scout on naming). Mounted in `AppModule`, covered by the real-boot schema test.
- **D-03:** Stable codes in `errors[0].extensions.code`, Phase 2/02.1 pattern (typed exception with `extensions.code`): **`CHARACTER_NOT_FOUND`** when the caller has no current character (second call, loser of two concurrent calls, stale client); `UNAUTHENTICATED` from the auth pipeline. Messages are Italian and user-facing; codes never change.

### Soft delete semantics (user decision 2026-10-15: archive, never purge)
- **D-04:** The `Character` document **stays in the collection**, marked with **`deletedAt: Date`** (default `null` on every existing/new document) and **`deletionReason`** (`user_request` now; `death` reserved for Phase 9). No other field is altered: name, status, quests and assets remain readable for audit and future mechanics.
- **D-05:** **Atomic unlink, same pattern as creation (02.1 D-03/D-17):** inside a replica-set transaction, (1) claim the user with `findOneAndUpdate({ _id: userId, currentCharacter: { $ne: null } }, { $set: { currentCharacter: null } })` capturing the previous id, (2) `updateOne({ _id: characterId, deletedAt: null }, { $set: { deletedAt, deletionReason } })`. If the claim finds no character → `CHARACTER_NOT_FOUND`, nothing written. Two concurrent calls → exactly one archive, the loser gets `CHARACTER_NOT_FOUND` (driver retries `WriteConflict`, as in 02.1). The response `User` is re-read after the commit (populated `currentCharacter` = `null`).
- **D-06:** **Archived characters are invisible on player paths** — fail-closed, the same way as a non-existent id: `character(id)` → `NOT_FOUND`; `characterUpdated(id)` → rejected at subscribe like a foreign id (`FORBIDDEN`/`NOT_FOUND`, planner picks the code already used by Phase 3 for "not yours"); every ownership-guarded mutation on an archived id is refused; the Bull spell-recovery processor and every future job (travel, Phase 8) must filter `deletedAt: null`. A single shared query helper/filter (e.g. `activeCharacterFilter`) is preferred over scattered conditions. The innkeeper-only `characters` list may include archived documents **only** behind an explicit argument (default: exclude) — planner's choice, additive.
- **D-07:** **No `characterUpdated` for archived documents:** the characters change-stream publisher skips `fullDocument.deletedAt != null` (the archiving update itself would otherwise emit one last event). Belt and braces with the Phase 3 ownership re-filter (the owner no longer owns it).
- **D-08:** **`userUpdated` needs no code:** the `users` change stream (Phase 3 D-02) already emits the full `User` on the `currentCharacter: null` update. Covered by an integration test on the wire.

### Name release
- **D-09:** The archived character's **name becomes available again** for `createCharacter` (FE E2E: delete → recreate with the same name). The case-insensitive unique index `character_name_ci_unique` (02.1 D-05, `CharacterNameIndexVerifier`) must stop covering archived documents. Options for the planner (research flag — verify what MongoDB 8 accepts in `partialFilterExpression`, e.g. `{ deletedAt: { $type: 'null' } }` vs a boolean `archived: false` flag; `$exists: false` is **not** allowed): **(a)** partial unique index on active documents; **(b)** a dedicated indexed key (e.g. `infos.nameKey`) `$unset` on archive, sparse unique index. Either way the boot verifier is updated to build the new index (and drop the old definition once), logging without blocking boot as in 02.1 D-32-style verifiers. `infos.name` stays readable on the archived document.

### Pending state and cross references
- **D-10:** **Archive regardless of pending state** (FE proposal accepted as default; open question 1 of the FE notes): today there is no `activeTravel`; `quests.pendingQuest` stays on the archived document. Phase 7 (quest lanes) and Phase 8 (travel lifecycle) must treat archived characters as absent (D-06 filter) — recorded as a note for those phases in `BACKEND-NOTES.md`.
- **D-11:** `twitchPoints` live on the `User` and are **untouched** by deletion (FE open question 4). No cooldown or limit on re-creation (open question 3).
- **D-12:** **Audit:** `deletedAt` + `deletionReason` on the document are the trace; **no** `admin_audit_logs` record (not an admin action). Phase 9 will reuse the same archive routine with `deletionReason: death`.

### TDD, tests, tooling
- **D-13:** Red → Green → Refactor. Integration tests on the replica-set harness (`createAuthTestApp` with the characters/creation imports, fixtures `persistCharacter`/`persistUser`): happy path (User with `currentCharacter: null`, document archived with `deletedAt`/`deletionReason`), second call → `CHARACTER_NOT_FOUND`, two concurrent calls → one archive, `character(id)` of an archived character → `NOT_FOUND`, `characterUpdated(id)` on an archived id rejected and no event emitted by the archiving update, `userUpdated` emits `currentCharacter: null`, `createCharacter` with the archived name succeeds, spell-recovery processor ignores archived characters. Unit tests for the filter helper and the exception.
- **D-14:** Tooling discipline (02.1 D-14): `npx prettier --write <file>` + `npx eslint <file>` on touched files only (never `npm run lint`); jest paths **before** `--selectProjects`; `src/schema.gql` regenerated by the real-boot test and committed (CI diff gate); beware `@graphql-yoga/subscription` `publish()` returns `void` (no `await`).
- **D-15:** Handoff: write this phase's `BACKEND-NOTES.md` (BE-CHAR-09) in the 02.1/03 style (TL;DR, SDL verbatim, codes, archive semantics, answers to the FE open questions 1–4, notes for Phases 5/7/8/9), and update the FE pointer in `Klimmeck-Guide/.planning/phases/04-settings-screen/BACKEND-NOTES.md` only if final names diverge.
- **D-16:** Branch `feat/03.1-character-deletion-contract` from `develop`, PR to `develop`, **merged before the FE Phase 4 PR**.

## Existing Code Insights

- `CharacterCreationService.claimUserAndInsertCharacter` — transaction + `findOneAndUpdate` claim on `users`; the deletion is the inverse claim.
- `CharacterCreationException` + `CharacterCreationErrorCode` — pattern for a lifecycle exception carrying `extensions.code`.

- `formatDomainError` — keeps `extensions.code` on the wire for `HttpException`s with a code.

### Established Patterns
- Identity-bound mutations without ids in input; `User` returned and re-read after commit.
- Change-stream publishers with `fullDocument: 'updateLookup'` and `$match` on `operationType` (filterable on `fullDocument` fields in the handler).
- Ownership re-filter on every live `characterUpdated` event (Phase 3, fail-closed).

### Integration Points
- `AppModule` imports; `src/schema.gql`; `CharactersService` read paths; `SpellRecoveryProcessor`; future Phase 7/8 jobs.
