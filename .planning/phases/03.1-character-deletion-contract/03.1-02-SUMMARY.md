# Phase 03.1 Plan 02: Partial character name index Summary

**Archived character names can be reused. The case-insensitive unique index `character_name_active_ci_unique` now covers only active characters (`partialFilterExpression: { deletedAt: null }`, which also covers legacy documents that lack the field). The boot verifier builds this index first and only then drops the legacy `character_name_ci_unique` index, once. It tolerates IndexNotFound (code 27) and never throws.**

## Accomplishments

- `INDEX_NOT_FOUND_ERROR_CODE = 27` and `isIndexNotFoundError(error)`, which reuses the private `mongoErrorCodeOf`.
- `CharacterSchema` declares a single index on `infos.name`. It is named `character_name_active_ci_unique`, is unique, uses the `{ locale: 'en', strength: 2 }` collation, and has `partialFilterExpression: ACTIVE_CHARACTER_FILTER`. `LEGACY_CHARACTER_NAME_INDEX` is exported for the migration.
- `CharacterNameIndexVerifier.onApplicationBootstrap()`:
  - If `createIndexes()` fails, it logs the error as before and returns. The legacy index is left in place.
  - If it succeeds, `dropLegacyNameIndex()` drops `character_name_ci_unique` and logs `Dropped legacy index character_name_ci_unique: archived character names are reusable`.
  - If the legacy index is already gone (code 27), nothing is logged.
  - Any other drop error is logged with `describeMongoError` and the method does not throw.
  - Log messages contain only index names, never character names.
- `test/authz/player-fixture.ts`: the comment now names the new index (Pitfall 8).
- An E11000 on the new index is still recognized by `isDuplicateKeyOn(error, 'infos.name')`, so `CHARACTER_NAME_TAKEN` behaves as before. The character-creation resolver int-spec is green.

## Deviations from Plan

**1. [Formatting] `dropIndex(LEGACY_CHARACTER_NAME_INDEX)` is split across two lines**
- **Found during:** Task 2
- **Issue:** The acceptance grep expects `dropIndex(LEGACY_CHARACTER_NAME_INDEX)` on one line. With 4-space indentation that call is longer than Prettier's print width, so Prettier puts the argument on the next line.
- **Fix:** The code follows the Prettier format. The call is present at `src/characters/creation/character-name-index.verifier.ts:46-48`, and its behavior is covered by int-spec cases 6 and 9.
- **Commit:** 14393f1

**2. [Test hygiene] Every test restores all mocks in `afterEach`**
- **Found during:** Task 1
- **Issue:** The old `errorSpy.mockRestore()` call would not restore the new `logSpy`, `createIndexes` and `dropIndex` spies.
- **Fix:** `afterEach` now calls `jest.restoreAllMocks()`, as the plan's behavior text says.
- **Commit:** e922e39

## Deploy Note (for plan 06)

On the first boot after deploy the app logs `Dropped legacy index character_name_ci_unique: archived character names are reusable`. The production DB user needs the `dropIndex` privilege on `characters`. Without it, the legacy index stays, an error is logged, and archived names stay reserved. Boot still succeeds.
