# Phase 03.1 Plan 04: Archived characters out of real time and jobs Summary

**The `characters` change stream now runs on `CHARACTER_CHANGES_PIPELINE`, whose `$match` includes `'fullDocument.deletedAt': null`. Because the stream uses `updateLookup`, this suppresses both the archiving update and every later write to an archived character, so no `characterUpdated` is emitted, not even to the innkeeper. The archive race in the handler (`ResourceNotFoundException`) is now skipped silently. `SpellRecoveryProcessor` reads characters through `findOne(activeCharacterById(characterId))`, so a job queued before archiving no longer modifies the archived character.**

## Accomplishments

- `src/characters/character-changes.pipeline.ts` exports `CHARACTER_CHANGES_PIPELINE`, in the same style as `USER_CHANGES_PIPELINE`.
- `CharactersService.onModuleInit` passes `CHARACTER_CHANGES_PIPELINE` to `watch`. The local `const pipeline` is gone, and the `catch` returns early on `ResourceNotFoundException`. `publish` is still not awaited.
- `SpellRecoveryProcessor.handleSpellRecovery` uses `findOne(activeCharacterById(characterId))` (no more `findById`). Its warn message is `Character <id> not found or archived, skipping recovery`, which contains only the id and never a name.
- Wire coverage:
  - silence after a sentinel event, for the innkeeper and the former owner;
  - later writes to an archived character produce no PubSub event;
  - no `'Errore nel change stream'` is logged;
  - `characterUpdated(id)` on an archived id is rejected with `NOT_FOUND` and then completed, for the former owner, another adventurer and the innkeeper.
- Subscriptions that are already open when a character is archived stay open and silent; they are not completed. Plan 06 documents this.
- `src/schema.gql` is unchanged.

## Deviations from Plan

**1. [Formatting] `watch(CHARACTER_CHANGES_PIPELINE` spans two lines**
- **Found during:** Task 2
- **Issue:** On one line the call is longer than prettier's 80 columns. Prettier formats it as `this.characterModel.watch(\n CHARACTER_CHANGES_PIPELINE,\n { fullDocument: 'updateLookup' },\n)`. As a result, the acceptance grep `grep -n "watch(CHARACTER_CHANGES_PIPELINE"` and the single-line key_link regex do not match.
- **Fix:** None needed. The behavior is as specified: the unit spec pins the pipeline, and the wire specs prove the suppression. `grep -n "CHARACTER_CHANGES_PIPELINE" src/characters/characters.service.ts` finds the import and the `watch` argument. This is the same situation as the plan 03 policy-grep deviation.
- **Files modified:** src/characters/characters.service.ts
- **Commit:** 21aea7d
