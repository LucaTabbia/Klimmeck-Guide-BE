# Phase 03.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest 30 + ts-jest 29, projects `unit` (`*.spec.ts`) / `integration` (`*.int-spec.ts`, MongoMemoryReplSet condiviso via `test/setup/{global-setup,global-teardown,after-env,mongo-replset,redis}.ts`) |
| **Config file** | `package.json` → `jest.projects` |
| **Quick run command** | `npx jest src/characters/deletion src/models/character src/mongo src/authz --selectProjects unit` |
| **Full suite command** | `npm test` (= `test:unit` + `test:int --runInBand`) |
| **Estimated runtime** | unit ~5 s; int-spec singolo ~3–8 s; `npm test` ~1–2 min |

Trappole di tooling (vincolanti, 02.1 D-14 / 03 VALIDATION): path jest PRIMA di `--selectProjects`; integration sempre `--runInBand` (le suite condividono il replica set: senza, decine di failure spurie); MAI `npm run lint` (solo `npx prettier --write <file>` + `npx eslint <file>` sui file toccati); `src/schema.gql` si rigenera con `npx jest test/app.int-spec.ts --selectProjects integration --runInBand` e si committa; `publish()` di `@graphql-yoga/subscription` restituisce `void` (no `await`).

---

## Sampling Rate

- **After every task commit:** quick run unit sui path toccati + il singolo int-spec toccato (`npx jest <file> --selectProjects integration --runInBand`)
- **After every plan wave:** `npm run test:unit && npx jest src/characters src/authz src/users test/app.int-spec.ts --selectProjects integration --runInBand`
- **Before `/gsd-verify-work`:** `npm test` verde, `npm run build` ok, eslint pulito sui file toccati, `git diff --exit-code src/schema.gql`
- **Max feedback latency:** ~45 s per task (int-spec WS)
