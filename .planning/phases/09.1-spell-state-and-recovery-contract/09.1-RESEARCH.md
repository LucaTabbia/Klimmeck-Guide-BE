#### Modello dati
- **D-03:** **`status.spellStates: [{ spell: ObjectId(ref Spell), usages: Int, recoveries: [Date] }]`** è l'**unica fonte di verità** di usi e recuperi. Invarianti: una voce per ogni id di `status.spells` e viceversa (stesso ordine); `0 ≤ usages ≤ spell.maxUsages`; `recoveries` crescente; `recoveries.length == maxUsages − usages` quando ogni recupero è tracciato (i job legacy di D-06 possono lasciarla più corta, mai più lunga).

Il campo GraphQL `ActiveSpell.usages` **resta sul filo** (il FE lo tratta come deprecato) e deve valere sempre quanto lo stato: la ricerca sceglie tra (a) mirror atomico in `assets.activeSpells.$[a].usages` con `arrayFilters` nello stesso `updateOne` dello stato, e (b) rimozione di `usages` dal documento Mongo e risoluzione al confine di lettura (populate/mapper condiviso da query, subscription e ogni altro percorso che serve `Character`). Nessun tipo esistente cambia forma; `EquipSpellRequest.usages` resta deprecato (nessuno lo invia). `src/schema.gql` rigenerato da `test/app.int-spec.ts`, diff solo additivo. `spell` popolato come oggi `status.spells`.

#### Scritture
- **D-06:** `useSpell` (e i consumi degli esiti: `outcome-writer.service.ts` / `spellsSpent` di `outcome-plan.ts`, override del GM): la magia deve essere **attiva** (`assets.activeSpells.spell`) con `usages ≥ 1` nello stato; un solo `updateOne` condizionale fa `$inc usages −1` e `$push recoveries dueAt` (con `$sort` crescente) sulla voce di `spellStates` (+ il mirror di D-04a se scelto), `dueAt = now + spell.recoveryTime` (ms, orologio `Clock`). Il job Bull `recover` porta `{ characterId, spellId, dueAt }`; il processor restituisce l'uso con un update idempotente: `$inc usages +1` e `$pull recoveries: dueAt`, condizionato a `usages < maxUsages` **e** `recoveries` contenente `dueAt`; i **job legacy** senza `dueAt` (in Redis prima del deploy) fanno `$inc +1` con la sola guard `usages < maxUsages` e rimuovono il primo istante se presente. Il filtro **non richiede più che la magia sia attiva** (D-01); salta solo personaggi archiviati/mancanti e magie non più conosciute. ## Summary

Il codice di oggi tiene usi e recuperi **nello slot** (`assets.activeSpells[].usages`): `equipSpell` scrive `usages: maxUsages` (`src/characters/spells/active-spell.updates.ts:31-35`), il processor incrementa solo se la magia è attiva (`active-spell.updates.ts:69-83`), `useSpell` compensa e lancia `SPELL_RECOVERY_UNAVAILABLE` se la coda rifiuta (`src/characters/characters.service.ts:353-375`), gli esiti della Phase 9 riscrivono `assets.activeSpells` dal piano (`src/quests/outcomes/outcome-plan.ts:188-226, 317-319`). Nessun istante di recupero è persistito: oggi il DB non è la fonte di verità dei recuperi.

Le sonde sull'harness hanno confermato che il modello del CONTEXT funziona con **due correzioni obbligatorie** (Research flags F2/F3): (1) `$pull recoveries: dueAt` rimuove **tutti** i duplicati — e i duplicati sono legittimi (un esito che spende 2 usi nello stesso istante produce due `dueAt` identici) — quindi un job restituirebbe 1 uso cancellando 2 istanti, e un uso andrebbe perso per sempre (sonda C); il credito corretto è `$inc +1` + `$pop: -1` (rimuove l'istante più vecchio) condizionato a `recoveries.0 ≤ now` e `usages < maxUsages`, provato idempotente e senza doppio credito sotto 6 tentativi concorrenti (sonda D); (2) la regola legacy «rimuovono il primo istante se presente» consuma l'istante di un uso **nuovo** e lascia un deficit che nessuno restituirà; la regola corretta accredita solo il **deficit non tracciato** (`usages + |recoveries| < maxUsages`, sonda E). `$inc` + `$push {$each,$sort}` sulla stessa voce e il mirror `assets.activeSpells.$[a].usages` funzionano nello stesso `updateOne` (sonda B); un `arrayFilters` su `assets.activeSpells` **assente** fa fallire l'update con code 2 (sonda B2), quindi la migrazione deve garantire l'array.

**D-04:** raccomando **(a) mirror atomico**, con il mapper già esistente di `CharactersService.findOne` (`characters.service.ts:176-192`) che legge `usages` dallo stato. Tutti i percorsi FE (query `character`, publisher `characterUpdated`, snapshot di subscribe) passano da `findOne`, ma esistono altri percorsi che servono `Character` senza mapper (`characters` dell'innkeeper, `User.currentCharacter` di `me`/`user`/`users`/`userUpdated`/`createCharacter`/`deleteCharacter`) e tre lettori di gioco leggono `activeSpells.usages` dal documento: con (b) `ActiveSpell.usages: Int!` risolverebbe `null` su quei percorsi e romperebbe `characters` per intero. La migrazione/verifier è una sola update pipeline idempotente (due run: 6 → 0 documenti modificati, snapshot identici, sonda G').

**Primary recommendation:** stato `status.spellStates` tipizzato con `MongooseSchema.Types.ObjectId` (mai `Types.ObjectId`, che diventa `Mixed`), mirror atomico in ogni scrittura degli usi, credito unico `$inc`+`$pop` condiviso da processor e sweep, job trigger con `dueAt` e `jobId` deterministico, migrazione/verifier come update pipeline idempotente al boot più migrazione «lazy» per personaggio nel processor (che parte prima del boot hook).

### Pattern 1: Modello `SpellState` (ref castato, non `Mixed`)
**What:** sottodocumento tipizzato; `spell` con `MongooseSchema.Types.ObjectId` (STATE [Phase 02]: «`Types.ObjectId` diventa `Mixed` in Mongoose 8»).
**Evidence:** sonda A — `spellStates` → `Array`, `spell` → `ObjectId`, `recoveries` → `Array` di `Date`; per confronto `status.spells` → `Array` di `Mixed`, `ActiveSpell.spell` → `Mixed` [VERIFIED: harness].
```typescript
// src/models/character/spell-state.model.ts
@ObjectType()
@Schema({ _id: false })
export class SpellState {
    @Field(() => Spell)
    @Prop({ type: MongooseSchema.Types.ObjectId, ref: Spell.name, required: true })
    spell: Types.ObjectId | Spell;

    @Field(() => Int)
    @Prop({ type: Number, required: true })
    usages: number;

    // ordinati crescenti: il primo è il prossimo uso che torna (D-02)
    @Field(() => [Date])
    @Prop({ type: [Date], default: [] })
    recoveries: Date[];
}
export const SpellStateSchema = SchemaFactory.createForClass(SpellState);

// character-status.model.ts, accanto a spells
@Field(() => [SpellState])
@Prop({ type: [SpellStateSchema], default: [] })
spellStates: SpellState[];
```
Un documento senza il campo idrata `[]` (sonda populate: `Array.isArray` true) — ma con `.lean()` il campo manca: i lettori lean usano `?? []`.

### Pattern 2: `useSpell` = un solo update su stato + mirror
**Evidence:** sonda B — `$inc` + `$push { $each, $sort: 1 }` sulla stessa voce + `$inc` sul mirror in un `updateOne` → `modifiedCount 1`, istanti ordinati anche inserendo un `dueAt` più vecchio, duplicati conservati; magia non attiva → il filtro `a` non matcha nulla, nessun errore [VERIFIED: harness].
```typescript
// spell-state.updates.ts
export const spellStateArrayFilters = (spellId: Types.ObjectId) => ({
    arrayFilters: [
        { 's.spell': spellId },                       // path castato: basta l'ObjectId
        { 'a.spell': { $in: idForms(spellId) } },     // path Mixed: entrambe le forme (04 Pitfall 1)
    ],
});

export function useSpellFilter(characterId: Types.ObjectId, spellId: Types.ObjectId) {
    return {
        ...activeCharacterById(characterId),
        'assets.activeSpells.spell': { $in: idForms(spellId) },               // attiva (D-06)
        'status.spellStates': { $elemMatch: { spell: spellId, usages: { $gte: 1 } } },
    };
}

export function spendUsagesUpdate(dueAt: readonly Date[]) {
    return {
        $inc: {
            'status.spellStates.$[s].usages': -dueAt.length,
            'assets.activeSpells.$[a].usages': -dueAt.length,                 // mirror D-04a
        },
        $push: { 'status.spellStates.$[s].recoveries': { $each: [...dueAt], $sort: 1 } },
    };
}
// characters.service.ts: updateOne(useSpellFilter(c, s), spendUsagesUpdate([dueAt]), spellStateArrayFilters(s))
```

### Pattern 3: Credito unico (processor + sweep) = `$inc +1` + `$pop -1`
**What:** «restituisci l'uso dell'istante più vecchio già scaduto». Ogni istante pushato corrisponde a un uso mancante: chi consuma quale istante è indifferente, il totale dei crediti è sempre pari agli istanti scaduti.
**Evidence:** sonda D — voce con `[T100, T100, T99999]`, `now = T200`, 6 `updateOne` concorrenti → esattamente 2 crediti (`110000`), resta `[T99999]`; altra voce con un solo istante scaduto, 3 tentativi concorrenti → 1 credito; replay → `matchedCount 0`; personaggio archiviato → `matchedCount 0`; il mirror con ref legacy a stringa viene aggiornato tramite `idForms` [VERIFIED: harness].
```typescript
export function dueCreditFilter(characterId: Types.ObjectId, spellId: Types.ObjectId, maxUsages: number, now: Date) {
    return {
        ...activeCharacterById(characterId),
        'status.spellStates': {
            $elemMatch: { spell: spellId, usages: { $lt: maxUsages }, 'recoveries.0': { $lte: now } },
        },
    };
}
export const CREDIT_DUE_USAGE = {
    $inc: { 'status.spellStates.$[s].usages': 1, 'assets.activeSpells.$[a].usages': 1 },
    $pop: { 'status.spellStates.$[s].recoveries': -1 },
};
// SpellRecoveryService.recoverDue: ripete l'updateOne finché modifiedCount === 1 (al massimo maxUsages volte)
```
Il filtro **non** controlla che la magia sia attiva (D-01); controlla che sia conosciuta implicitamente (la voce di stato esiste solo per magie conosciute).

### Pattern 4: Job = trigger, `jobId` deterministico per istante
```typescript
export interface SpellRecoveryJobData { characterId: string; spellId: string; dueAt?: number } // epoch ms
export const spellRecoveryJobId = (c: Types.ObjectId, s: Types.ObjectId, dueAt: Date) =>
    `spell-${c.toHexString()}-${s.toHexString()}-${dueAt.getTime()}`;   // niente ':' (travel-job.ts:16)
```
- `jobId` deterministico: due usi nello stesso istante producono un solo job (Bull ignora il secondo `add`), che restituisce **tutti** gli istanti scaduti di quella magia (`recoverDue` in loop). Con `removeOnComplete: true` un `add` successivo con lo stesso id è di nuovo accettato.
- Processor (`@Process('recover')`): dati malformati → WARN e return; `dueAt` presente e `> clock.now()` → LOG «in anticipo: lo restituirà lo sweep» e return (specchio di `src/travel/travel-completion.processor.ts:33-38`); `dueAt` presente → `migrateOne(characterId)` poi `recoverDue`; `dueAt` assente → `migrateOne` poi `recoverLegacy` (Pattern 5). Catalogo mancante → WARN e return (oggi `spell-recovery.processor.ts:45-54`).

### Pattern 5: Job legacy = credito del solo deficit non tracciato
**Evidence:** sonda E — voce `usages 1`, `recoveries [futuro]`, `maxUsages 3` (deficit non tracciato = 1), 4 crediti legacy concorrenti → esattamente 1 (`0010`), l'istante futuro resta intatto [VERIFIED: harness].
```typescript
export function legacyCreditFilter(characterId: Types.ObjectId, spellId: Types.ObjectId, maxUsages: number) {
    return {
        ...activeCharacterById(characterId),
        $expr: {
            $let: {
                vars: { s: { $first: { $filter: {
                    input: { $ifNull: ['$status.spellStates', []] },
                    cond: { $eq: ['$$this.spell', spellId] },
                } } } },
                in: { $and: [
                    { $ne: ['$$s', null] },
                    { $lt: [{ $add: ['$$s.usages', { $size: { $ifNull: ['$$s.recoveries', []] } }] }, maxUsages] },
                ] },
            },
        },
    };
}
export const CREDIT_LEGACY_USAGE = {
    $inc: { 'status.spellStates.$[s].usages': 1, 'assets.activeSpells.$[a].usages': 1 },
};
```

### Pattern 6: `equipSpell` come update pipeline (mirror copiato dallo stato)
**Evidence:** sonda F — la pipeline appende `{ spell: ObjectId, usages: <usages dello stato> }`, la seconda esecuzione non matcha (`$nin`), il ref salvato è un `ObjectId` [VERIFIED: harness]. Mongoose 8 accetta l'array come update (già usato da `src/economy/coins.expressions.ts:29`); la pipeline **non** è castata: passare solo `Types.ObjectId`.
```typescript
export function equipSpellUpdate(spellId: Types.ObjectId, maxUsages: number) {
    const stateUsages = { $let: {
        vars: { s: { $first: { $filter: { input: { $ifNull: ['$status.spellStates', []] },
                                         cond: { $eq: ['$$this.spell', spellId] } } } } },
        in: '$$s.usages',
    } };
    return [{ $set: { 'assets.activeSpells': { $concatArrays: [
        { $ifNull: ['$assets.activeSpells', []] },
        [{ spell: spellId, usages: { $ifNull: [stateUsages, maxUsages] } }],
    ] } } }];
}
```
`equipSpellFilter` (`active-spell.updates.ts:14-29`) resta identico; `unequipSpellUpdate` (`:47-51`) resta identico (lo stato non si tocca).

### Pattern 7: Esiti della Phase 9 = `$set` dello stato calcolato dallo snapshot in sessione
Gli esiti leggono il personaggio **dentro** la transazione (`resolution-loader.service.ts:262-277`, chiamato da `quest-resolution.service.ts:101`, `boss-resolution.service.ts:114`, `gm-completion.service.ts:244`, `rescue-resolution.service.ts:335`) e scrivono un solo `$set` (`outcome-plan.ts:307-336`). Un credito concorrente fuori transazione provoca `WriteConflict` e la callback viene rieseguita su uno snapshot fresco.
**Evidence:** sonda H — transazione: lettura in sessione, credito esterno concorrente, poi `$set` dello stato calcolato → `attempts 2`, stato finale corretto (credito e spesa entrambi applicati) [VERIFIED: harness].
Quindi `spellsSpent` calcola in memoria la nuova voce (usi − taken, `recoveries` = merge ordinato con `taken` copie di `now + recoveryTime`) e il piano aggiunge `'status.spellStates': <array intero>` e `'assets.activeSpells': <mirror con gli usi dello stato>` al `$set` esistente; l'apprendimento (`outcome-plan.ts:320-322`) aggiunge nello stesso `$set` sia `status.spells` sia la voce `{ spell, usages: maxUsages, recoveries: [] }`. `SpellRecovery` diventa `{ characterId, spellId, dueAt }` e `OutcomeWriter.deliver` accoda con `enqueueTrigger` (oggi `outcome-writer.service.ts:187-215` usa `delay: delayMs` dal commit e un `jobId` casuale).

### Pattern 8: Migrazione / verifier = una update pipeline idempotente
**Evidence:** sonda G' su 8 documenti (legacy stringa in `status.spells`, `assets` senza `activeSpells`, id spazzatura + magia orfana nel catalogo, mirror divergente, stato con voce orfana, vuoto senza campo, coerente, archiviato) → run 1: `matched 6 / modified 6`; run 2: `0 / 0`; snapshot identici; archiviato e coerente intatti [VERIFIED: harness]. Pipeline nella sezione Code Examples.

### Pattern 9: Sweeper (copia di `TravelSweeper`)
`onApplicationBootstrap`: `setInterval(...).unref()` se `sweepIntervalMs > 0`, poi `void this.sweepSafely()`; `sweep()` single-flight con `inFlight ??=`; `onModuleDestroy` con `stopping` e attesa dell'in-flight (come `quest-resolution.sweeper.ts`); log solo id e codici (`src/travel/travel-sweeper.ts:25-105`). Query: `find({ ...ACTIVE_CHARACTER_FILTER, 'status.spellStates.recoveries': { $lte: now } }, { 'status.spellStates': 1 }).lean()`; un `find` del catalogo per gli id coinvolti (`maxUsages`); per ogni voce con `recoveries[0] ≤ now` → `recoverDue`. Granularità: default 60 000 ms (D-09); nessuna ragione di cambiarla.

### Anti-Patterns to Avoid
- **`$pull` per valore su `recoveries`:** cancella i duplicati (sonda C).
- **Due write separate per stato e mirror:** due change event → un'emissione `characterUpdated` intermedia divergente (viola il criterio D-04).
- **`@Prop({ type: Types.ObjectId })` per `SpellState.spell`:** diventa `Mixed`, niente cast (Phase 4 Pitfall 1, STATE [Phase 02]).
- **Stringhe esadecimali nelle pipeline:** non vengono castate; solo `Types.ObjectId`.
- **`$$NOW` nei filtri:** sempre `clock.now()` (convenzione Phase 8/9, testabilità con `FixedClock`).
- **Credito con filtro «attiva»:** viola D-01.

## Common Pitfalls

### Pitfall 1: `$pull` di un istante duplicato
**What goes wrong:** due usi nello stesso istante (esito con `usages: 2`, `outcome-plan.ts:213-219`) → `$pull dueAt` toglie entrambi gli istanti con un solo `+1`.
**How to avoid:** credito `$inc` + `$pop: -1` (Pattern 3). **Warning sign:** test con due `dueAt` uguali che finisce con `usages < max` e `recoveries` vuoto.

### Pitfall 2: `arrayFilters` su un array assente
**What goes wrong:** `The path 'assets.activeSpells' must exist in the document in order to apply array updates` (code 2) — sonda B2, sia con `assets: {}` sia senza `assets`. È un'**eccezione**, non `matchedCount 0`: un job fallirebbe e lo sweep loggherebbe un errore a ogni giro.
**How to avoid:** la migrazione scrive sempre `assets.activeSpells` (anche `[]`) e `migrateOne` precede ogni credito; la creazione scrive già `[]`.

### Pitfall 3: ref orfano nel catalogo
**What goes wrong:** `populate('status.spellStates.spell')` lascia `null` per una magia cancellata dal catalogo (sonda populate), `SpellState.spell: Spell!` → errore che risale fino a `Character.status` e rompe `character`/`characterUpdated`; `status.spells` invece scarta l'orfano (lunghezza 1 su 2).
**How to avoid:** il mapper di `findOne` scarta le voci con `spell` non popolato, mantenendo l'ordine di `status.spells`.

### Pitfall 4: ref non popolato sui percorsi `User.currentCharacter` e `characters`
**What goes wrong:** un `ObjectId` non popolato ha `.id` = Buffer (sonda populate) → «ID cannot represent value: Buffer» se un client seleziona `spellStates { spell { id } }` lì. Stesso comportamento di oggi per `status.spells`.
**How to avoid:** handoff: selezionare `spellStates` solo su `character`/`characterUpdated` (è già così nel FE). Nessun cambio a `UsersService` in questa fase.

### Pitfall 5: processor prima della migrazione
**What goes wrong:** job scaduti durante il downtime partono in `onModuleInit`, prima del migrator → credito su un documento senza stato → uso perso.
**How to avoid:** `migrateOne(characterId)` nel processor prima del credito.

### Pitfall 6: `$getField` e versione Mongo di produzione
**What goes wrong:** `$getField` richiede MongoDB ≥ 5.0; la versione di produzione non è verificata (blocker in STATE).
**How to avoid:** usare `$let` + `'$$s.usages'` (forma usata in Pattern 5/6 e nella pipeline finale).

### Pitfall 7: fixture con usi solo nel mirror
**What goes wrong:** decine di test scrivono `assets.activeSpells: [{ spell, usages }]` senza `status.spells`/`spellStates` (es. `quest-combat.int-spec.ts:288-290`): dopo la fase `useSpell` e `spellsSpent` non trovano la voce di stato.
**How to avoid:** helper Wave 0 `spellBook(...)` che produce `status.spells`, `status.spellStates`, `assets.activeSpells` coerenti.

### Pitfall 8: `.env.example` con modifiche non committate dell'utente
**What goes wrong:** l'executor aggiunge `SPELL_RECOVERY_SWEEP_INTERVAL_MS` e con `git add .env.example` committa anche le righe `SIGHTENGINE_*` dell'utente; `git add -p` è interattivo (non disponibile).
**How to avoid:** Flag F8.

### Pitfall 9: ordine dei campi nello SDL
`spellStates` precede `spells` (ordinamento lessicografico per code point); un test che si aspetta l'ordine inverso fallisce.

### Pipeline di migrazione / verifier (provata, sonda G')
```typescript
// spell-state.updates.ts — catalog = [{ id: Types.ObjectId, maxUsages: number }] letto una volta al boot
const arr = (path: string) => ({ $ifNull: [path, []] });
const first = (input: unknown, cond: unknown) => ({ $first: { $filter: { input, cond } } });
const pick = (doc: unknown, field: string) => ({ $let: { vars: { d: doc }, in: `$$d.${field}` } });
const KNOWN = { $filter: {
    input: { $map: { input: arr('$status.spells'),
        in: { $convert: { input: '$$this', to: 'objectId', onError: null, onNull: null } } } },
    cond: { $ne: ['$$this', null] },
} };
const stateOf = (id: string) => first(arr('$status.spellStates'), { $eq: ['$$this.spell', id] });
const sameRef = (a: string, b: string) => ({ $eq: [{ $toString: a }, { $toString: b }] });

export function spellStatesConsistentExpr() {
    return { $and: [
        { $eq: [{ $map: { input: arr('$status.spellStates'), in: '$$this.spell' } }, KNOWN] },
        { $eq: [{ $type: '$assets.activeSpells' }, 'array'] },
        { $eq: [{ $type: '$status.spellStates' }, 'array'] },
        { $allElementsTrue: [{ $map: { input: arr('$assets.activeSpells'), as: 'a', in: { $eq: [
            '$$a.usages',
            pick(first(arr('$status.spellStates'), sameRef('$$this.spell', '$$a.spell')), 'usages'),
        ] } } }] },
    ] };
}

export function spellStatesRepairPipeline(catalog: readonly { id: Types.ObjectId; maxUsages: number }[]) {
    const maxOf = (id: string) => pick(first({ $literal: catalog }, { $eq: ['$$this.id', id] }), 'maxUsages');
    const activeUsagesOf = (id: string) =>
        pick(first(arr('$assets.activeSpells'), sameRef('$$this.spell', id)), 'usages');
    return [
        { $set: { 'status.spellStates': { $map: { input: KNOWN, as: 'k', in: { $ifNull: [
            stateOf('$$k'),
            { spell: '$$k', usages: { $ifNull: [activeUsagesOf('$$k'), { $ifNull: [maxOf('$$k'), 0] }] }, recoveries: [] },
        ] } } } } },
        { $set: { 'assets.activeSpells': { $map: { input: arr('$assets.activeSpells'), as: 'a', in: {
            spell: '$$a.spell',
            usages: { $ifNull: [pick(first('$status.spellStates', sameRef('$$this.spell', '$$a.spell')), 'usages'), '$$a.usages'] },
        } } } } },
    ];
}
// migrazione:  updateMany({ ...ACTIVE_CHARACTER_FILTER, 'status.spellStates': { $exists: false } }, pipeline)
// verifier:    updateMany({ ...ACTIVE_CHARACTER_FILTER, $expr: { $not: [spellStatesConsistentExpr()] } }, pipeline)
```
Nota: la sonda ha usato `$getField` dove qui c'è `$let` (Pitfall 6): il test RED della pipeline va eseguito sulla forma `$let`. Esiti osservati: legacy stringa → `ObjectId`; magia inattiva → `maxUsages`; attiva → usi del mirror; `assets: {}` → `activeSpells: []`; id spazzatura scartato; voce di stato orfana scartata; mirror riallineato allo stato; archiviato e coerente intatti.

### Mapper di `findOne` (estensione di `characters.service.ts:176-192`)
```typescript
// spell-state.mapper.ts — puro, testato unit; usages dallo stato (D-03), ordine degli slot da activeSpells, orfani scartati
export function spellsOnTheWire(status: { spells: Spell[]; spellStates: SpellState[] }, active: ActiveSpell[]) {
    const known = new Map(status.spells.map((spell) => [spell.id, spell]));
    const states = status.spellStates.filter((s) => s.spell && (s.spell as Spell).id && known.has((s.spell as Spell).id));
    const usagesOf = new Map(states.map((s) => [(s.spell as Spell).id, s.usages]));
    const activeSpells = active.flatMap((a) => {
        const id = refIdOf(a.spell)?.toHexString();
        const spell = id ? known.get(id) : undefined;
        return spell ? [{ spell, usages: usagesOf.get(id!) ?? a.usages }] : [];
    });
    return { spellStates: states, activeSpells };
}
```

### Known Threat Patterns
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| client che invia `usages` o istanti | Tampering | input ignorato; `dueAt` solo da `Clock` server; nessun campo nuovo negli input |
| replay di un job Bull (at-least-once) | Tampering | credito condizionato a un istante scaduto presente (sonda D2: `matched 0`) |
| sweep ∥ processor ∥ replay | Tampering | stesso update condizionale; 6 concorrenti → crediti = istanti scaduti (sonda D) |
| job forgiato in Redis | Elevation | al massimo anticipa il trigger: il credito richiede `recoveries.0 ≤ now` o un deficit non tracciato e `usages < maxUsages` |
| spesa concorrente durante un esito | Tampering | transazione con snapshot in sessione → `WriteConflict` → retry (sonda H) |
| personaggio archiviato | Information/Tampering | `activeCharacterById` in ogni filtro (sonda D2), sweep su `ACTIVE_CHARACTER_FILTER`, change stream già filtrato (`character-changes.pipeline.ts`) |
| log con dati sensibili | Information Disclosure | solo id e codici (pattern `codeOf` di `travel-sweeper.ts:26-32`) |
| DoS dello sweep | DoS | single-flight, loop per voce limitato a `maxUsages`, intervallo configurabile; indice rinviato alla Phase 10 |
