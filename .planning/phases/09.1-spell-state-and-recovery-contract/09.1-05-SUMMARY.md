## Per i piani 06 e 07

Ecco la forma esatta di `equipSpellUpdate` (`src/characters/spells/active-spell.updates.ts`):

```typescript
export function equipSpellUpdate(spellId: Types.ObjectId, maxUsages: number) {
    const stateUsages = { $let: {
        vars: { state: { $arrayElemAt: [
            { $filter: { input: { $ifNull: ['$status.spellStates', []] }, cond: { $eq: ['$$this.spell', spellId] } } },
            0,
        ] } },
        in: '$$state.usages',
    } };
    return [{ $set: { 'assets.activeSpells': { $concatArrays: [
        { $ifNull: ['$assets.activeSpells', []] },
        [{ spell: spellId, usages: { $ifNull: [stateUsages, maxUsages] } }],
    ] } } }];
}
```

- Ritorna un **array** (pipeline), non tipizzato esplicitamente. La pipeline non viene castata, quindi `spellId` deve essere un `Types.ObjectId`.
- `equipSpellFilter(characterId, spellId)` **non cambia**: la magia è conosciuta (`status.spells $in idForms`), non è attiva (`assets.activeSpells.spell $nin idForms`), e la capacità si valuta sul documento vivo (`$expr $lt [$size, maxActiveSpellsExpression()]`). Anche `unequipSpellFilter` e `unequipSpellUpdate` (`$pull` del ref, stato intatto) non cambiano.
- Il confronto `$$this.spell` con `spellId` vale solo per la forma ObjectId. Le voci di stato sono sempre ObjectId castati (`SpellStateSchema`, migratore 09.1-03), quindi una voce di stato in forma stringa non esiste.
- `characters.service.ts`:
  - `equipSpell` legge ancora `maxUsages` dal catalogo (`NOT_FOUND` se la magia manca) ed esegue un solo `updateOne(equipSpellFilter(c, s), equipSpellUpdate(s, spell.maxUsages))`. Ignora `request.usages`. Se `matchedCount` è 0 chiama `classifySpellFailure`, come prima. È cambiato solo il commento.
  - `unequipSpell` non cambia.
  - `useSpell`, `recoverSpellFilter` e `INCREMENT_ACTIVE_SPELL_USAGE` non sono stati toccati e restano compito del piano 06.
  - `active-spell.updates.spec.ts` importa ancora i builder legacy che il piano 06 rimuove.
