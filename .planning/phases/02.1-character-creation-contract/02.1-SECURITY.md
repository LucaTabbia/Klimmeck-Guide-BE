# Phase 02.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| client -> `CreateCharacterInput` | Ogni campo e' controllato dal client; il validator e' l'unica difesa applicativa | name, sex, pronoun, race, classType, age, background, imagePath (non fidati) |
| client -> `createCharacter` (identita') | Identita' dal JWT verificato dal guard globale, mai dall'input | bearer / `AuthIdentity.userId` |
| resolver -> client GraphQL | Ogni errore passa da `formatDomainError` | codici e messaggi di dominio (fissi) |
| MongoDB -> service | Errori driver (E11000 con `keyValue`/chiave ICU) non devono raggiungere il client | errori driver |
| service -> MongoDB (transazione) | Scritture multi-documento User + Character | `User.currentCharacter`, Character |
| dati City/POI -> stato del personaggio | Dati di seed possibili incompleti/malformati | `markerLocation` |
| server -> log | Log di boot su stdout della piattaforma | messaggi verifier/reporter |
| harness di test -> produzione | Override solo nell'app di test; `src/` non importa da `test/` | fixture |
| documentazione -> repo | BACKEND-NOTES committato, senza secret | testo |
