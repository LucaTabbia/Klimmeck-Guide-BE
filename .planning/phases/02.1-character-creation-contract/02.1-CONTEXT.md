# Phase 02.1: Character Creation Contract - Context

**Gathered:** 2026-10-09
**Status:** Ready for planning (post-research refinements D-16..D-21 added 2026-10-09)

<domain>
## Phase Boundary

Give the frontend one authenticated mutation that creates the caller's character and sets `User.currentCharacter`, with the backend owning every rule: input validation (name, age by race, background, enums), the starting state (location by race, level, title, coins, HP, empty assets), atomic "one character per user", stable error codes, and a `raceTraits` query that exposes the race/age table the app needs to drive its form. Plus the handoff (`BACKEND-NOTES.md`) consumed by FE Phase 2.

Out of scope: NSFW moderation of portraits (deferred to BE-HARD by the user), admin creation of characters for other users (Phase 3 role work), character deletion/reset, curated portrait sets, any change to the existing `POST /cloudinary/uploadImage` beyond what the plan finds strictly necessary.

</domain>

<decisions>
## Implementation Decisions

### Contract
- **D-01:** Mutation **`createCharacter(input: CreateCharacterInput!): User!`**. Identity comes only from `@CurrentUser()` (BE-AUTH-06): no `userId`/`twitchId` in the input. Returns the updated `User` with `currentCharacter` populated (same shape the `me` query returns), so the app can swap its session user without a second round trip.
- **D-02:** Input fields: `name: String!`, `sex`, `pronoun`, `race`, `classType` (the existing TS enums `SexType`, `PronounType`, `RaceType`, `ClassType`), `age: Int!`, `background: String` (optional), `imagePath: String` (optional URL). Exposing the four enums as registered GraphQL enum types (they are already `registerEnumType`'d) is preferred over `String`: the app sends `enum.name` strings either way.
- **D-03:** **One character per user, atomic.** The `currentCharacter` assignment is a conditional update (`findOneAndUpdate({ _id, currentCharacter: null }, …)`); a user who already has a character — including the loser of two concurrent calls — gets `CHARACTER_ALREADY_EXISTS` and **no partial document remains** (transaction on the replica set, or compensating delete of the just-created character: planner's choice, both covered by an integration test).
- **D-04:** Stable error codes in `errors[0].extensions.code`, following the Phase 2 pattern (typed `GraphQLError` subclasses): `CHARACTER_NAME_INVALID`, `CHARACTER_NAME_TAKEN`, `CHARACTER_AGE_OUT_OF_RANGE`, `CHARACTER_ALREADY_EXISTS`, `STARTING_LOCATION_UNAVAILABLE`; enum/length violations the GraphQL layer does not already reject use the generic validation code (`BAD_USER_INPUT`). Messages are Italian and user-facing; codes never change.

### Validation (authoritative — the app's live validation is UX only)
- **D-05:** **Name:** trimmed, internal whitespace collapsed to single spaces, 2–20 characters, only Unicode letters (`\p{L}`), spaces, apostrophes (`'` and `’`) and hyphens; **unique case-insensitive** across all characters. Uniqueness is enforced by the database (unique index on a normalized key such as `infos.nameKey`, or a case-insensitive collation index) and `E11000` maps to `CHARACTER_NAME_TAKEN`. Existing characters without the key need a one-off backfill or a lazily-computed key — planner decides.
- **D-06:** **Age by race** — single source of truth, a TypeScript constant module (e.g. `src/characters/race-traits.ts`) used by both the validator and the `raceTraits` query. Table **aligned to the lore** (accepted by the user on 2026-10-09; supersedes the D&D-inspired table first proposed in the FE discuss):

  | race | minAge | maxAge | lore |
  |---|---|---|---|
  | human | 16 | 200 | 60–70 normally, mages beyond 200 |
  | elf | 100 | 9999 | infinite life, >1000 common |
  | halfelf | 16 | 130 | 120–130 |
  | dwarf | 40 | 140 | 130–140 |
  | gnome | 16 | 60 | ~60 |
  | halfling | 16 | 70 | ~70 |
  | dragonborn | 16 | 180 | 150–180 |
  | tiefling | 16 | 120 | 100–120 |
  | aarakocra | 3 | 40 | 30–40 |

- **D-07:** **Background:** optional, ≤ 500 characters after trim. Absent/blank is stored as the empty string (`infos.background` stays `String!` in the schema — no breaking change for existing consumers).
- **D-08:** **imagePath:** optional; when present it must be an `https` URL (light check: the Cloudinary secure URL returned by `POST /cloudinary/uploadImage`, folder `characters_profile`). **No NSFW moderation in this phase** (user decision 2026-10-08); recorded as BE-HARD debt.

### Starting state (backend-owned)
- **D-09:** `status`: `level 1`, `title rookie`, `xp 0` (→ `maxActiveSpells` virtual = 0, spells unlock later by design), `currentLifePoints 100`, `maxLifePoints 100`, `coins { gold 0, silver 5, copper 0 }` (user: "5 monete di argento"), `injuries []`, `spells []`. `quests`: `completedQuests []`, `pendingQuest null`. `assets`: `ownedEquipments []`, `ownedItems []`, `wearedEquipment {}`, `activeSpells []`, `pet null`. No starting equipment (user decision).
- **D-10:** **Starting location by race** (lore, confirmed by the user): the character is born on the `markerLocation` POI of a `City` whose `type` is the race's home:

  | race | home `CityType` |
  |---|---|
  | elf | `elfCapital` (Minnely forest, Drustea) |
  | gnome, dwarf, tiefling | `motherCapital` (Regno della Madre) |
  | halfling | `liberiaCapital` |
  | aarakocra | `aarakocraVillage` (Altopiani) |
  | dragonborn | `mountainVillage` (monti Lamstone) |
  | human, halfelf | **random** among `drusteaCapital`, `valanCapital`, `mirwaCapital`, `liberiaCapital` |

  The mapping lives next to the age table (same module). If more than one City has the type, pick one at random; if none exists in the database, the mutation fails with `STARTING_LOCATION_UNAVAILABLE` and creates nothing. No boot-time check (data may legitimately be seeded later), but a WARN log at startup for missing home cities is welcome.

### Query
- **D-11:** **`raceTraits: [RaceTraits!]!`** with `race: RaceType!`, `minAge: Int!`, `maxAge: Int!` — authenticated like everything else (no `@Public()`). Home cities are not exposed (the app does not need them); adding them later is additive.

### TDD, tests, tooling

Unit tests for the validator and the race-traits module; **integration tests on the replica-set harness** for: happy path (User returned with `currentCharacter`, Character persisted with D-09/D-10 state), second call → `CHARACTER_ALREADY_EXISTS`, two concurrent calls → exactly one character, duplicate name case-insensitive → `CHARACTER_NAME_TAKEN`, age out of range, missing home city → `STARTING_LOCATION_UNAVAILABLE`. Reuse `test/fixtures` (add a City fixture: none exists today) and `createAuthTestApp` for the authenticated GraphQL call.
- **D-13:** Handoff: write this phase's `BACKEND-NOTES.md` (BE-CHAR-05) in the Phase 2 style (TL;DR, contract, examples, codes, starting state), and update the FE notes pointer in `Klimmeck-Guide/.planning/phases/02-character-creation/BACKEND-NOTES.md` only if the final names diverge from the proposal there.
- **D-14:** Tooling discipline: `npx prettier --write <file>` + `npx eslint <file>` on touched files only (never `npm run lint`); jest paths **before** `--selectProjects`; regenerate `src/schema.gql` by booting the app or the schema-generation path used in Phase 2.

### Authorization note
- **D-15:** Phase 3 (ownership/roles) has not landed: `createCharacter` is identity-bound by construction (D-01) and needs no ownership guard. No innkeeper variant that creates characters for others in this phase.

### Post-research refinements (2026-10-09 — see `02.1-RESEARCH.md`; they bind the planner)
- **D-16 (refines D-04):** The Phase 2 pattern is **not** a `GraphQLError` subclass: `AuthException extends UnauthorizedException` and its code reaches the client only through `formatAuthError`. Do the same here: a `CharacterCreationException extends BadRequestException` carrying `extensions.code`, and widen the shared formatter (rename to `formatDomainError`, accept any HttpException with a string `extensions.code`, update `graphql-options.factory.spec`). A raw `GraphQLError` subclass would make Nest log a stack trace for every bad input.
- **D-17 (fixes D-03):** **Transaction (pattern A)** — inside `connection.transaction()`: first `findOneAndUpdate({ _id: userId, currentCharacter: null }, { $set: { currentCharacter } })` with a pre-generated `ObjectId`, then `Character.create([doc], { session })`. Verified: 3 concurrent calls → exactly one character, losers get `CHARACTER_ALREADY_EXISTS`; a duplicate-name error rolls back the user update. Compensating delete is rejected (orphan on crash).
- **D-18 (fixes D-05):** **Unique index on `infos.name` with collation `{ locale: 'en', strength: 2 }`** — no `nameKey`, no backfill. E11000 arrives with `keyPattern { 'infos.name': 1 }`; its `keyValue` is an opaque ICU key and must never be echoed. Add a boot-time index verifier modelled on `TwitchIdIndexVerifier` (a failed index build is otherwise silent). Normalize the name to **NFC** before the `\p{L}` check.
- **D-19 (user decisions on the name, 2026-10-09):** the typographic apostrophe **`’` is normalized to `'`** before validation and storage (so "D'Arcy" and "D’Arcy" collide); the name must contain **at least one Unicode letter** (punctuation-only names such as "--" are rejected with `CHARACTER_NAME_INVALID`).
- **D-20 (model traps):** ObjectId refs in these schemas are stored as `Mixed` (no casting): always pass `Types.ObjectId` values. `assets.wearedEquipment: {}` must be set explicitly or `CharactersService.findOne` and the GraphQL field break. `UsersService.findOne` populates one level only: the mutation's `User` carries `currentCharacter { id … }` shallowly — the app loads the full character with `character(id)` as it already does.
- **D-21 (module & tests):** The new code lives in its **own Nest module** (e.g. `src/characterCreation/`) without Bull, so tests do not need Redis; `createAuthTestApp` gains an `imports` option and an injectable `RandomSource` override; call `model.init()` in `beforeAll` so indexes exist before uniqueness/transaction tests; authenticate tests with `createAuthenticatedUser`, not the dev bypass. Schema regeneration: `npx jest test/app.int-spec.ts --selectProjects integration --runInBand`, then commit `src/schema.gql` (CI fails on drift). Inserting a character publishes nothing on the change stream (it watches update/replace only) — fine for this phase.
- **Image host allowlist** (restricting `imagePath` to the Cloudinary host) stays a "light check" per D-08 and is recorded as BE-HARD debt.

### Claude's Discretion

- Random source for human/half-elf home and multi-city picks (injectable for deterministic tests).
- Exact validation code for enum/length violations when GraphQL already rejects them.
- Whether to log missing home cities at boot (D-10).
