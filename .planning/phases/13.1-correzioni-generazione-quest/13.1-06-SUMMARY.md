# Phase 13.1 Plan 06: One-off delle tappe delle dungeon v2 Summary

Tappe delle dungeon fisse ricomposte una volta al primo boot reale: 2–4 tappe senza animali né leggendari, dal pool del POI, con Σ xp × quantità nel budget a un posto del `minTitle` e il primo nemico conservato quando lascia spazio; il boot ora esegue nemici → reset → hunt → dungeon → richiesta di corsa al generatore.

## Cosa è stato fatto

### Task 1 — regole pure (`dungeon-stages.ts`)
- `DUNGEON_STAGES_SEED = 1313`, `DUNGEON_STAGES = { min: 2, max: 4 }`, `STAGE_ATTEMPTS = 20`.
- `isCoherentDungeon(stages, byId, rank)`: ogni nemico in `byId` con `animal === false` e `legendary === false`, ogni `xp × quantity ≤ RANK_XP_BANDS[rank].max`, 2–4 tappe, Σ in `budgetOf(rank, 1)`.
- `dungeonStagesOf(input): DungeonStage[] | null`: pool = `zonePoolOf` ristretto a 1 ≤ xp ≤ hi, se vuoto `fallbackPoolOf` ristretto allo stesso modo, se vuoto `null`; testa = `current[0]` se nel pool e `xp × quantity ≤ hi − minXp`; un tiro per `k` (2–4); per tentativo (fino a 20) un tiro per tappa estratta, quantità 1; se nessun tentativo riesce con la testa si riprova senza (stesso `k`), poi `null`.
- `dungeonTitleOf(enemy, city)` = `Dungeon: ${enemy} presso ${city}` (template della Phase 11).
- Helper privati: `indexOf`, `inBudget`, `sumOf`, `isStageEnemy`, `stagePoolOf`, `nextStageOf`, `attemptOf`, `drawStages`, `headOf`, interfaccia `StageDraw`.

### Task 2 — migratore e boot
- `DungeonStagesMigrator` ctor posizionale `(questModel, enemyModel, loreModel, poiModel, cityModel)` = `@InjectModel` Quest, Enemy, Lore, PointOfInterest, City; `migrate(): Promise<DungeonStagesReport>` con `DungeonStagesReport = { recomposed; coherent; skipped }`.
- Lettura `OPEN_DUNGEON` (`'infos.type': dungeon, concludedAt: null, startedAt: null`) ordinata per `_id`; nessuna dungeon ⇒ report a zero senza altre letture. Mondo: `readEnemyCandidates` + `byId`, tipi dei POI (`stringsOf`), POI → nome della prima città per `_id` che lo elenca in `pointsOfInterest` (`refIdOf` su ogni voce).
- Per dungeon: `minTitle` non `isGeneratedRank` ⇒ WARN `Dungeon <id> con minTitle non generabile: saltata` (skipped); coerente ⇒ coherent; `null` ⇒ WARN `Dungeon <id> senza tappe componibili: lasciata` (skipped); altrimenti `updateOne` con filtro `{ _id, ...OPEN_DUNGEON }` che imposta `infos.enemies` (ObjectId) e, solo se il primo nemico cambia e la città esiste, `infos.title` = `dungeonTitleOf`. INFO `Dungeon: R ricomposte, C già coerenti` solo se R > 0.
- `QuestMaintenanceBoot` ctor `(enemies, reset, hunts, dungeons: DungeonStagesMigrator, trigger)`; passo `tappe delle dungeon (una tantum)` fra le hunt e la richiesta. `QuestMaintenanceModule`: provider `DungeonStagesMigrator` (forFeature invariato, aveva già tutti i modelli).
