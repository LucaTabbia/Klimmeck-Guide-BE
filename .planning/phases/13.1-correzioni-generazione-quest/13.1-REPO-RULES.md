## Lint, format, test

- MAI `npm run lint` (esegue `eslint --fix` su tutto il repo) né `npm run format`, né prettier su una directory: solo `npx prettier --write <file>` e `npx eslint <file>` sui file `.ts` toccati, uno per uno (in zsh una variabile con più percorsi NON si spezza). Un file da modificare che fallisce GIÀ `npx prettier --check <file>` riceve PRIMA un commit separato `style(<scope>): format <file>` (solo Prettier), poi la modifica. `package.json` non passa prettier: mai formattarlo.
- Jest: `npx jest <percorsi> --selectProjects unit` / `npx jest <percorsi> --selectProjects integration --runInBand`, con i percorsi PRIMA di `--selectProjects`; integration sempre `--runInBand`; MAI jest in background; a fine di OGNI task `pgrep -fl jest` non stampa nulla (`pgrep` vuoto esce 1: non concatenarlo con `&&`). Per task si esegue solo la spec mirata; la suite completa (`npm run test:cov`) gira solo nel piano di gate.
- Type check: `npx tsc --noEmit -p tsconfig.json` esce 0 a fine di ogni task di codice (ts-jest non fa type check: un test verde può nascondere un errore tsc; con `target: esnext` gli import di soli tipi vengono elisi e un RED arriva come «is not a function»). **Mai `npm run build` né `nest build`** (`nest-cli.json` ha `deleteOutDir: true` e il processo BE dell'utente, `node dist/main.js` pid 68075 sulla porta 3001, gira da `dist/` di questo stesso albero): la build vera la lancia l'orchestratore al boot reale.

Nessun `jest.mock(` di moduli: override di provider. Nessuna rete nei test. Prove di assenza con `toEqual` sull'intero output o `Object.keys(...).sort()`, mai con un grep sul letterale. RNG dei test sempre iniettato (`SequenceChance`/`SeededChanceSource`, seme fisso): nessun `Math.random` nei moduli di generazione e nei migratori.
