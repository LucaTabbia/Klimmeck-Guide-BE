# Phase 13.1 — Validation Strategy

> Contratto di validazione della fase: ogni task degli 8 piani (26 task) ha un comando automatico; le spec nuove nascono nel commit RED del proprio task (nessun piano Wave 0 separato).

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Jest 30 + ts-jest (progetto `unit` = `*.spec.ts`, progetto `integration` = `*.int-spec.ts` su `MongoMemoryReplSet` condiviso) |
| **Config file** | `package.json` → `jest.projects`, `jest.coverageThreshold` (soglia `./src/quests/generation/` della Phase 13) |
| **Quick run command** | `npx jest <percorsi> --selectProjects unit` · `npx jest <percorsi> --selectProjects integration --runInBand` (percorsi PRIMA di `--selectProjects`) |
| **Full suite command** | `npm run test:cov` (solo nel piano di gate 13.1-07) |
| **Schema gate** | real boot `npx jest test/app.int-spec.ts --selectProjects integration --runInBand`, poi `git diff --exit-code src/schema.gql` e `git diff origin/develop -- src/schema.gql` vuoto |
| **Type gate** | `npx tsc --noEmit -p tsconfig.json` a fine di ogni task di codice (mai `npm run build`: il BE dell'utente gira da `dist/`) |
| **Estimated runtime** | ~3 s per spec unit mirata, ~6–15 s per int-spec mirata; suite completa alcuni minuti |

---

## Sampling Rate

- **After every task commit:** la spec mirata del task (unit o integration) + `npx tsc --noEmit -p tsconfig.json`
- **After every plan wave:** le spec della directory toccata (`src/quests/generation`, `src/quests/maintenance`, `src/quests`), real boot nei piani che toccano resolver o moduli montati in `AppModule` (04, 05, 06)
- **Before `/gsd-verify-work`:** `npm run test:cov` verde (piano 07)
- **Max feedback latency:** 60 seconds per task
