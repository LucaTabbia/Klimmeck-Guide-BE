<plan_notes>
- Eccezione dichiarata alla regola dei log: D-07 chiede che il server logghi l'errore INTERO con il `requestId`. Il plugin e il sanitizer WS loggano `logger.error(\`Errore interno ${requestId}: ${describeError(error)}\`, error instanceof Error ? error.stack : undefined)` (lo stack va nel secondo argomento del Logger di Nest); nessun dato della richiesta (variabili, header, token) entra nel log.
- Regola del sanitizer (solo produzione): un errore formattato con `extensions.code` assente o uguale a `INTERNAL_SERVER_ERROR` diventa `{ message: 'Errore interno', locations, path, extensions: { code: 'INTERNAL_SERVER_ERROR' } }` (il `requestId` lo aggiunge il plugin su HTTP, il sanitizer su WS); ogni altro errore diventa `{ message, locations, path, extensions: { code } }`. Fuori produzione `formatError` resta `formatDomainError`.
- Firme graphql-ws 6.0.6 (verificate dal RESEARCH): `validate?(schema, document)`, `onNext?(ctx, id, payload, args, result)`, `onError?(ctx, id, payload, errors)`; il valore restituito sostituisce il risultato/gli errori. Nest passa `subscriptions['graphql-ws']` a `useServer` così com'è.
- `hideSchemaDetailsFromClientErrors` esiste in `@apollo/server` 4.12.2; `ApolloServerPluginLandingPageDisabled` si importa da `@apollo/server/plugin/disabled`.
</plan_notes>
